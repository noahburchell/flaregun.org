1. more terminal commands?

im just rambling from memory here, so maybe use read the section about how to read terminal commands. i use the terminal for pretty much everything, and these are the commands i use all the time so they must be important but ill also probably forget some and add them later

also, these arent man pages so go read them too

1.1. ls, cd

ls will list everything in your current working directory. usually, when you open the terminal this will be /home/user (~ is a shortcut for /home/user). so if you run ls right now, you may see "Documents", "Downloads", etc.

cd will move you into a directory. lets say you just ran ls, and you want to go to documents: since ls listed "Documents" in your current directory, you can type cd Documents to go there

1.2. "." ".."

. is your current directory. so if you run ls and see "Documents", cd ./Documents is equivelant to cd Documents

.. is the parent directory. if you just ran cd Documents, you will be in /home/user/Documents. so running cd ../ will move you back to ~

1.3. file manipulation

this may be the second most common use of the terminal next to package management. so its important to know how to view, create, move, and edit files without opening a file manager. im going to assume nano for this guide, if you installed vim or mg, ill assume you know how to use them

i dont want to type this super long filename:

luckily, you have tab completion. start typing a file or directory name then press tab and the shell fills in the rest (if what your looking for exists). hit tab twice to see every option.

spaces in filenames? cat my file.txt looks for a file called "my" and one called "file.txt". quote it like cat "my file.txt" or escape the space cat my\ file.txt. tab completion does this for you

also, most linux native filesystems is case sensitive so Documents and documents are two different directories

looking at files:

  • cat foo.txt: prints the whole file
  • less foo.txt: opens the file in a pager you can scroll through. q to quit, /word to search, n for the next match
  • ls -l: lists files with their size, owner, permissions and modification date. ls -a also shows hidden files, ls -la does both
  • file foo: tells you what file a file is

making, copying, moving:

  • mkdir foo: makes a directory. mkdir -p foo/bar/baz makes all of those at once if they dont exist
  • touch foo.txt: makes an empty file
  • cp foo.txt bar.txt: copies a file foo.txt to bar.txt
  • mv foo.txt bar.txt: moves a file. this is also how you rename things

note that cp and mv will overwrite an existing file with the same name without asking. add -i if you want to be asked

another difference: mv (on the same drive) is instant and all or nothing, the file either has the old content or the new content. cp rewrites the destination bit by bit, so if its interrupted or something reads it mid-copy, you get a half-written file1. this is why the safe way to replace a file is to write the new version somewhere else and mv it over the top

when does cp or rsync copy only the contents of the directory into the new directory versus copying the whole directory into the directory making it a subdirectory of the new directory? honestly, i dont fucking know. it seems to flip a coin.

deleting:

rm deletes files, rm -r deletes directories, and none of it goes to the trash. i covered this in dont lose your data. if you want a terminal command that actually uses the trash, gio trash foo probably will work, or install trash-cli and use trash-put foo

editing with nano:

nano foo.txt opens the file (or creates it). the bottom of the screen shows the shortcuts. ^ means ctrl and M- means alt. here are common ones:

  • ctrl+o: save
  • ctrl+x: exit
  • ctrl+w: search
  • ctrl+k: cut the current line, ctrl+u to paste it back
  • alt+u: undo
  • ctrl+g: help

if the file is owned by root (most of /etc), you will need {sudo | doas} nano /etc/<file>2

wildcards:

you will see * in a lot of commands. the shell expands it to "every file that matches", so ls *.txt lists every file ending in .txt and cp ~/Pictures/*.png /backup/ copies every png. this is useful and also how rm -rf $DIR/* goes wrong (see dont lose your data)

1.4. ln

the most common use of the ln (link) command is creating a symlink. the syntax is ln -s <target> <link name>, and the target is relative to the link

💡 tip: you can create a symlink in a folder that points to the parent folder, creating a loop. this is actually completely useless, though

1.5. grep

grep is pretty much control s (search) (it stands for global regular expression print). it is one of the best commands. to use it, you either search a file directly, or pipe somehting into it. to search foo.txt for any mention of foo, you can do this: grep "foo" foo.txt, to search dmesg for nvidia, you can do this: [sudo | doas] dmesg | grep "nvidia". to search foo.txt for any match of "Foo", "fOo", etc (ignoring case), you can use: grep -i "foo" foo.txt. another common flag combo is this: [sudo | doas] dmesg | grep -iE "amd|video|card". that will search dmesgs output for any mention of amd, video, or card, case insensitively.

1.6. du

disk useage, -h makes the sizes readable, and -a includes files. so pretty much you can use du -hd 1 ~ (-d 1 specifies max depth to look, you can try it with and without on your home dir to see the difference) to see the disk useage of all folders in your home dir, and use du -ahd 1 ~ to include the files too

2. permissions

youve already seen this: sudo mkdir ./<dir> gave you a directory you cant write to, and an appimage wont run until chmod +x. both are permissions. "permission denied" is probably one of the most common errors youll see

also, "permissions" means three different things on linux and people mix them up:

  1. unix file permissions (this section)
  2. selinux / apparmor (see selinux and apparmor)
  3. app sandboxes like flatpak (see flatpak and appimage)

2.1. basics

every file has an owner and a group. then it has three sets of permissions for the owner, the group, and everyone else. run ls -l and look at one line 

-rw-r--r-- 1 noah noah 1234 Nov  1 00:00 foo.txt
drwxr-xr-x 2 noah noah 4096 Nov  1 00:00 Documents

the third column is the owner, the fourth is the group. the first column is the permissions themselves. so foo.txt is owned by user noah and group noah

2.2. what is -rw-r--r--

-rw-r--r-- has 1 character for the type, then 3 groups of 3 characters for perms

the first character: the file type. d directory, - regular file, l symlink, c character device, b block device, p named pipe and s socket

the next 3: the owner. r read, w write, x execute. - means no

the next 3: the group

the last 3: everyone else

  • -rw-r--r-- -> "a regular file, the owner can read and write it, everyone else can only read it".
  • drwxr-xr-x -> "a directory, the owner can do everything, everyone else can look around but not change anything"

if theres an 11th character (. or +), see selinux and apparmor

2.3. rwx is different for directories

here:

perm on a file on a directory
r read the contents list the names in it (ls)
w change it create, delete or rename things in it
x run it as a program enter it (cd) and access things in it by name

to delete a file you need w on the directory, so a read only file in a directory you own is still deletable by you. and a directory with r but no x lets you see names but not open any of them

2.4. who am i and what groups am i in

id tells you your user, your primary group and every other group youre in. groups are how you get access to things without being root. on most distros being in video gives you video card access, dialout gives you serial access (i think), docker lets you talk to docker without root (do not add yourself to docker group if you dont know the consequence4), wheel (or sudo on debian/ubuntu) is what lets you use sudo at all

add yourself to a group with {sudo | doas} usermod -aG <group> "$USER". without the -a, you replace your groups instead of adding one (not good). then log out and back in, group changes dont apply to sessions that are already open process

2.5. changing permissions

chmod changes rwx

  • chmod +x script.sh: make it executable (for everyone5) (also make sure you are holding shift and dont accidentally put =x, becasuse that does this weird bs where it makes it only exectable causing a weird error that you may spend too long trying to figure out….)
  • chmod u+w <file>: give the owner (u) write
  • chmod go-r secret.txt: take read away from group (g) and others (o)
  • chmod -R ...: do it recursively

guides will instead tell you chmod 755 or chmod 644. those are the same thing as numbers: r=4, w=2, x=1, add them up per set. so 7 is rwx, 6 is rw-, 5 is r-x, 4 is r--. the three digits are owner, group, other

  • 644: rw-r--r--, a normal file
  • 755: rwxr-xr-x, a script or a directory
  • 600 / 700: only you, used for secrets. ssh will actually refuse to work if ~/.ssh and the contents of it are too open

chown changes the owner and group: {sudo | doas} chown <user>:<group> <file>. the one youll actually use is fixing a root-owned directory: {sudo | doas} chown -R "$USER": ./<dir> (the trailing colon means "and my primary group")

dont chmod -R 777 things. it "fixes" the error by making the file writable by every program and user on the system. find out which permission is actually missing instead

2.6. root ignores some of this

root passes every rw(x) check, which is why sudo "fixes" permission errors (thats the wrong fix, see dont lose your data). root doesnt ignore the execute bit on files, immutable files, read only mounted filesystems and selinux/apparmour

2.7. permission denied, but ls -l says im allowed?

in order of likelihood:

  • you just added yourself to a group and havent logged out
  • the drive is fat32/exfat/ntfs. (permissions come from mount options, see backups)
  • the partition is mounted noexec, somewhat common for /tmp and usb drives
  • the directory above it is missing x for you
  • its a flatpak and the sandbox cant see that folder. fix it in flatseal
  • selinux or apparmor (see below)

2.8. selinux and apparmor

standard permissions tell you "is this user allowed". selinux and apparmor ask "is this program allowed to touch this at all", this is called mandatory access control (mac)

do i have this?:

  • anything fedora or rhel based: selinux. getenforce prints enforcing, permissive or disabled
  • ubuntu, debian: apparmor. {sudo | doas} aa-status lists the loaded profiles
  • arch, gentoo: probably neither unless you set it up
  • anything else: check! it should be easy to find if you look up your distro

if you dont have it, skip this section

common issues: you set up a web server (maybe using nhttp!), samba, game server or ssh, you move a file into its directory, ls -l says the permissions are fine, and the service still cant read it

with selinux thats because every file has a label (the 11th character . in ls -l means one is there, ls -Z shows it). a file created in /var/www gets a web label, a file moved there keeps the label from your home folder (remember, mv doesnt rewrite the file, see here1). [sudo | doas] restorecon -Rv <path> puts the correct labels back. to see what got denied, you can look at {sudo | doas} ausearch -m avc -ts recent, or on fedora just open the setroubleshoot notification, it explains it in english (i think, its been a while)

with apparmor its per program. each (confined) program has a profile in /etc/apparmor.d/ listing what it may touch, and your path isnt there. logs show up in [sudo | doas] dmesg | grep -i apparmor or [sudo | doas] journalctl -k | grep DENIED (with systemd). you can set one profile to complain mode (log but allow) with {sudo | doas} aa-complain <program> while you work out whats missing

dont turn it off (setenforce 0 / SELINUX=disabled)

it "fixes it", by removing it entirely. this is like disabling windows defender entirely becasue an app wont run, so dont do it. there is a proper permenant fix with semanage fcontext or somethign, im not going to cover that becasue i have no idea and dont use selinux. rhel docs are probably the best place to look

2.9. special perms

youll sometimes see s or t where an x should be, for example on /usr/bin/sudo and /tmp. s (setuid) on the owner slot means the program runs as its owner, t on a directory means you can only delete your own files in it

3. backups

youve heard the usual 3-2-1 advice many times so ill spare that, what is linux specific things you should backup.

3.1. what to backup

your home folder covers most of it, but some important stuff lives outside of it:

  • /etc: this is where system config is. fstab, network settings and third-party repos and the lot, treat this as somewhat sensitive tho be becasue it may contain wifi passwords and other shit. (is yours 12345678? i see you)
  • a list of your installed packages
    • pacman: pacman -Qqe > pkglist.txt
    • apt: apt-mark showmanual > pkglist.txt
    • dnf: dnf repoquery --userinstalled > pkglist.txt
    • zypper: im actually not sure, so look it up
    • portage: backup /var/lib/portage/world and everything in /etc/portage
    • flatpak: flatpak list --app --columns=application > flatpaks.txt
  • your kernel config (/usr/src/linux/.config) if you compile your own. you do not want to redo that from scratch
  • some of /var/lib: vms (/var/lib/libvirt/images), docker volumes (/var/lib/docker/volumes), databases. if you dont know what these are, you probably dont have any
  • /root and /var/spool/cron (if you dont know what this is it doesnt apply to you)

3.2. what not to backup

some stuff in home is big and useless to keep around:

  • ~/.cache: its literally cache
  • ~/.local/share/Trash: …
  • ~/.var/app/*/cache: flatpak app caches. keep the rest of ~/.var/app though, thats where flatpak apps keep their settings and data
  • steam games (~/.local/share/Steam/steamapps/common): theyre huge and you can just redownload them6. (unless youre still on vdsl, fuck you iinet!)
  • anything you can rebuild, like node_modules, or build folders

3.3. mistakes to avoid

  • hidden files: cp -r ~/* /backup skips hidden files. use rsync -aHAX ~/ /backup/ or some other tool. (or just backup hidden files manually)
  • if you copy to a fat32 or exfat usb, you lose permissions, ownership and symlinks,use a linux native filesystem
  • secrets: ~/.ssh and ~/.gnupg are in home, so they get backed up too. that means either exclude them and back them up separately and encrypted, or encrypt your whole backup
  • snapshots arent backups7

5. not every distro uses systemd

most guides you find online assume systemd, but its not the only init. if a guide tells you to run systemctl and you get "command not found", youre probably on one of these:

  • mx linux, antix, devuan: sysvinit
  • gentoo, alpine, artix: openrc (artix also offers runit, dinit, s6)
  • void: runit
  • youre a legend: ninit

not sure? cat /proc/1/comm tells you what your init is. (well, sysvinit shows as "init" so if it says that try rc-update to see what you have)

task systemd openrc runit
check a service systemctl status <service> rc-service <service> status sv status <service>
start a service systemctl start <service> rc-service <service> start sv up <service>
start on boot systemctl enable <service> rc-update add <service> ln -s /etc/sv/<service> /var/service/
logs journalctl -u <service> usually /var/log/ usually /var/log/
