* linux isnt windows
the old windows-isms of grabbing random executables off the web to install software, rebooting to
fix issues, and playing valorant, are gone. on linux, software is installed through the command line
using a package manager (see [[*package management][package management]]), through a gui app store (if your desktop
environment provides one), through flatpak, or with an appimage (see [[*flatpak and appimage][flatpak and appimage]]).

most issues on linux do not need a reboot, and most updates dont need one either[fn:atomic]. unless
the kernel, systemd (or whatever init youre using), graphics drivers (especially nvidia), or glibc
has been updated. a reboot could also help if you genuinely dont know where to start fixing an
issue. otherwise you can just leave it running

[fn:atomic] on an atomic distro like bazzite, every system update needs a reboot, because theyre
done as images. flatpak updates dont

** how to use the terminal
well, you first need to open one! if you have deliberately installed a terminal emulator, i can
assume you know what its called. but for people whove never thought about it, heres a list of the
default terminal installed with each desktop environment:

- kde: konsole
- gnome: gnome terminal (this changes a lot so just search for terminal or console)
- xfce4: xfce4-terminal

so just open it like any other app, then you should see something that looks like either one of
these:

#+begin_example
[user@host ~]$ 
user@host:~$ 
#+end_example

(note: for this guide ill use "user" and "host" as a placeholder for your username and hostname)

this is called a prompt. the important parts of each are the =user=, =host=, =~= and =$=. (the rest
is just decoration)

- =user=: your username
- =host=: your hostname
- =~=: your current working directory
- =$=: delimiter, it marks the end of the prompt (not important, just know as your user it is "=$="
  (or =%= for zsh), but as root its "=#=")

you can type text here and itll appear just after your prompt. so now lets go over some important
commands

** ls, cd
=ls= will list everything in your current working directory. usually, when you open the terminal
this will be =/home/user= (=~= is a shortcut for =/home/user=). so if you run =ls= right now, you
may see "Documents", "Downloads", etc.

=cd= will move you into a directory. lets say you just ran =ls=, and you want to go to documents:
since =ls= listed "Documents" in your current directory, you can type =cd Documents= to go there

** "=.=" "=..="
=.= is your current directory. so if you run =ls= and see "Documents", =cd ./Documents= is
equivelant to =cd Documents=

=..= is the parent directory. if you just ran =cd Documents=, you will be in =/home/user/Documents=.
so running =cd ../= will move you back to =~=

** sudo / doas
=sudo= and =doas= are privilege elevation tools that let permitted users run commands as root or
another user. for now, your can ignore the "other user" part and just think of it as running a
command as *root*.

*who is root?* root is the user account with the user id 0, now that probably doesnt mean much to
you, so just think of it as the administrator account. certain things you will need to do require
administrator privileges, the most common example is probably installing new software. see
[[*package management][package management]]

when you run a command with =sudo= or =doas=, a prompt will appear asking you to type your password.
often, it will provide no visual feedback. this is normal, it isnt frozen, its just not showing you
whats being typed. so, to get an idea, please open your terminal and type the command =sudo echo hi=
or =doas echo hi=. (if your not sure which tool you have installed, try sudo first as its the more
common one). you should see a prompt asking for your password. type your password in, and hit enter.
if you typed your password correctly and you have the required privileges, you should see "hi". if
you run the same command, it may not ask for your password, this is becasue sudo (and doas with
persist enabled) cache your credentials so you dont have to repeatedly type your password. if you
see an error such as "user is not in the sudoers file", it means your account does not have
administrator permissions

** file manipulation
this may be the second most common use of the terminal next to [[*package management][package
management]]. so its important to know how to view, create, move, and edit files without opening a
file manager. im going to assume =nano= for this guide, if you installed =vim= or =mg=, ill assume
you know how to use them

*i dont want to type this super long filename*:

luckily, you have *tab completion*. start typing a file or directory name then press tab and the
shell fills in the rest (if what your looking for exists). hit tab twice to see every option.

spaces in filenames? =cat my file.txt= looks for a file called "my" and one called "file.txt". quote
it like =cat "my file.txt"= or escape the space =cat my\ file.txt=. tab completion does this for you

also, most linux native filesystems is case sensitive so =Documents= and =documents= are two
different directories

*looking at files*:

- =cat foo.txt=: prints the whole file
- =less foo.txt=: opens the file in a pager you can scroll through. =q= to quit, =/word= to search,
  =n= for the next match
- =ls -l=: lists files with their size, owner, permissions and modification date. =ls -a= also shows
  hidden files, =ls -la= does both
- =file foo=: tells you what file a file is

*making, copying, moving*:

- =mkdir foo=: makes a directory. =mkdir -p foo/bar/baz= makes all of those at once if they dont
  exist
- =touch foo.txt=: makes an empty file
- =cp foo.txt bar.txt=: copies a file foo.txt to bar.txt
- =mv foo.txt bar.txt=: moves a file. this is also how you rename things

note that =cp= and =mv= will overwrite an existing file with the same name without asking. add =-i=
if you want to be asked

another difference: =mv= (on the same drive) is instant and all or nothing, the file either has the
old content or the new content. =cp= rewrites the destination bit by bit, so if its interrupted or
something reads it mid-copy, you get a half-written file[fn:inode]. this is why the safe way to
replace a file is to write the new version somewhere else and =mv= it over the top

when does =cp= or =rsync= copy only the contents of the directory into the new directory versus
copying the whole directory into the directory making it a subdirectory of the new directory?
honestly, i dont fucking know. it seems to flip a coin.

[fn:inode] =cp= truncates the existing file and writes into the same inode. =mv= on the same
filesystem is a =rename()=, which swaps the directory entry to point at the source inode. across
filesystems =mv= is just copy then delete and loses this property


*deleting*:

=rm= deletes files, =rm -r= deletes directories, and none of it goes to the trash. i covered this in
[[*dont lose your data][dont lose your data]]. if you want a terminal command that actually uses the
trash, =gio trash foo= probably will work, or install =trash-cli= and use =trash-put foo=

*editing with nano*:

=nano foo.txt= opens the file (or creates it). the bottom of the screen shows the shortcuts. =^=
means ctrl and =M-= means alt. here are common ones:

- =ctrl+o=: save
- =ctrl+x=: exit
- =ctrl+w=: search
- =ctrl+k=: cut the current line, =ctrl+u= to paste it back
- =alt+u=: undo
- =ctrl+g=: help

if the file is owned by root (most of =/etc=), you will need =sudo nano /etc/foo=[fn:sudoedit]

*wildcards*:

you will see =*= in a lot of commands. the shell expands it to "every file that matches", so =ls
*.txt= lists every file ending in .txt and =cp ~/Pictures/*.png /backup/= copies every png. this is
useful and also how =rm -rf $DIR/*= goes wrong (see [[*dont lose your data][dont lose your data]])

[fn:sudoedit] =sudoedit /etc/foo= is a better way to do this if you have sudo, it copies the file,
opens it as your normal user, and copies it back when you save

* dont lose your data
there are certain commands to pay *extra* attention to

=sudo / doas, rm, dd, curl | *=

=sudo / doas=: these commands were covered in [[*sudo / doas][sudo / doas]]. but i only covered how
to use them, not the places where it becomes a problem. never run a gui app as root, and if a
command doesnt work, running it with sudo often will not help unless the command genuinely needs
root. if you happen to run something like =sudo mkdir ./foo=, you will later run into issues where
you cannot make files in it. that is because the directory is owned by root and not your user. this
can be resolved with =sudo chown -R "$USER": ./foo=

=rm=: this command doesnt send something to the trash, it permanently deletes it and there is no
undo. the most common failure is most often not =rm -rf /= or something like that, but =rm -rf
$DIR/*=. =$DIR= should expand to =/home/user/some/trash=, but if it has been unset, it will expand
to "" and the command =rm -rf /*= will run. always wrap variables like this: =rm -rf "${DIR:?}"/*=.
(you might know that modern =rm= will block =rm -rf /= and you need the =--no-preserve-root= flag,
this is different becasuse =*= expands to all directories in root, which isnt protected)

=dd=: this command writes data somewhere, youll often see:

#+begin_example
dd if=/some/diskimage.iso of=/dev/sdX bs=4M status=progress conv=fsync
#+end_example

this is not inherently unsafe, its actually the standard way to create a bootable usb. it becomes
dangerous if =of=/dev/sdX= is the wrong location. luckily there is a small habit that makes it very
safe, always run =lsblk= before running =dd=. =lsblk= will show you all of the drives connected to
your computer, making it easy to determine the correct one.

*tip*: if you cant tell which device is your usb, run =lsblk=, unplug it, run =lsblk= again, then
plug it back in and run =lsblk= a third time. it will have dissapeared and came back

but just so you know, if the location you typed (for example =/dev/sda=) is your boot drive[fn:nvme]
or a drive with your stuff on it, depending on the size of the disk image, youll overwrite:

1. the protective mbr
2. the primary gpt header and partition table[fn:gpt]
3. the entire efi system partition (if its at the start of the drive)
4. the beginning of the next partition, and its superblock
5. if the input never ends (=if=/dev/zero=), then literally everything

*so always double check its correct with* =lsblk=

=curl https://example.com/example.sh | bash= or the more evil version =curl
https://example.com/example.sh | sudo bash=: these commands download a script from that site and
execute it immediately without showing you what its doing. never do this blindly. if a site wants
you to install their software like this, first make *sure* the site is trustworthy, then download it
alone (=curl -LO https://example.com/example.sh=), then use =ls= to check the filename, then with
that information run =less ./example.sh= to review it, then you can run it by first making it
executable (=chmod +x ./example.sh=), and executing it like so: =./example.sh=

*> vs >>*

i dont want to go too much into teaching shell, but this one difference is worth a note. these are
redirection operators, as an example: =echo "gentoo" > gentoo.txt= will do this[fn:cat]:

#+begin_example
noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ % 
#+end_example

now, lets look at what =>>= will do:

#+begin_example
noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ % echo "gentoo" >> gentoo.txt 
noah@lychee ~ % cat gentoo.txt             
gentoo
gentoo
noah@lychee ~ % 
#+end_example

now, lets use =>= again on the same file:

#+begin_example
noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ % echo "gentoo" >> gentoo.txt 
noah@lychee ~ % cat gentoo.txt             
gentoo
gentoo
noah@lychee ~ % echo "gentoo" > gentoo.txt 
noah@lychee ~ % cat gentoo.txt            
gentoo
noah@lychee ~ % 
#+end_example

notice the difference here, =>= will truncate the file[fn:truncate] and *replace* it with what its
given. =>>= on the other hand will append to the file, *not* overwriting the content. (if there is
no file, then they act the same for all intents and purposes)

i have lost 12h of log data from this very difference >:(

[fn:nvme] on a modern device with an nvme drive, =/dev/nvme0n1= is probably your boot drive

[fn:gpt] gpt keeps a backup header at the end of the disk, so the partition table can sometimes be
recovered

[fn:cat] the command =cat= (short for (con)catenate) is a very common command for writing the
content of a file or input stream to standard output. echo writes its arguments to standard output

[fn:truncate] truncation happens prior to the command executing, so =sort foo.txt > foo.txt= will
leave you with an empty file. in this case =sort -o foo.txt foo.txt= is correct

* package management
the most common way to install software on linux is through the package manager. common package
managers include: apt, dnf, pacman, zypper and portage. (note: for alternatives such as flatpak and
appimage, see [[*flatpak and appimage][flatpak and appimage]]). to communicate with these package
managers, you will use the terminal, here are examples for each of the package managers mentioned:

** apt

- installing a package: =apt install whatever=
- removing a package: =apt remove whatever= (or =apt purge whatever= to also delete config files)
- syncing repos: =apt update=
- updating everything: =apt upgrade=[fn:aptfull]
- searching for a package: =apt search whatever=

[fn:aptfull] =apt upgrade= wont remove packages, you may need =apt full-upgrade= occasionally


** dnf

- installing a package: =dnf install whatever=
- removing a package: =dnf remove whatever=
- syncing repos: =dnf makecache= (dnf usually does this automatically)
- updating everything: =dnf upgrade=
- searching for a package: =dnf search whatever=

** pacman

- installing a package: =pacman -S whatever=
- removing a package: =pacman -R whatever= (or =pacman -Rns whatever= to also remove unneeded
  dependencies and config files)
- syncing repos + updating everything: =pacman -Syu=[fn:partial]
- searching for a package: =pacman -Ss whatever=

[fn:partial] never use =pacman -Sy whatever=, partial upgrades are unsupported


** zypper

- installing a package: =zypper install whatever=
- removing a package: =zypper remove whatever=
- syncing repos: =zypper refresh=
- updating everything: =zypper update= (on tumbleweed use =zypper dup= instead)
- searching for a package: =zypper search whatever=

** portage

- installing a package: =emerge -a whatever=
- removing a package: =emerge -a --deselect whatever= then =emerge --depclean=
- syncing repos: =emerge --sync=
- updating everything: =emerge -auDN @world=
- searching for a package: =emerge --search whatever=

if youre unsure which package manager came with your distro, you can use the command =which apt dnf
pacman zypper emerge=, and the one that returns a path is the one you have. also installing or
updating packages and syncing most often requires root privileges, so make sure to run those
commands with =sudo= or =doas=

now that you know how to use it, its important to know what youre doing and why it is this way.
briefly, your distros maintainers have a "repo" (repository) that is pretty much a sort of database
of packages. it contains the package and metadata for each one that is used when you install that
package. this may include dependencies and packages its incompatible with. what is a dependency? its
/another/ package that the package needs to function correctly. so when you ask the package manager
to install a package, it may install a few packages alongside it if it depends on them. also, your
package manager will most likely verify the integrity of the package and that it came from a
trustworthy source after it downloads it (one of the many reasons this approach is far superior to
the windows approach). "syncing" just means updating the database.

** dont delete your desktop

you may have seen that... situation linus was in when he deleted his desktop using pop os. this was
caused by a packaging mistake with steam, but linus could have avoided this, and you can too, so
heres how:

just listen to your package manager! it sounds simple, of course, but many people tend to just hit
yes on autopilot. this is normal, but you should avoid this behavior as the output of your package
manager is *not* useless monospace text, its telling you *exactly* what it is going to do! now, you
might mention that you wouldnt know removing, say, glibc[fn:glibc] was any different to removing
libcaca, thats reasonable. so the best advice i can give you is to research anything youre unsure
about. scan the package managers output for keywords like "desktop" (gnome-desktop, plasma-desktop),
"system", "wayland", "xorg", "mesa", "base", "systemd" to make sure nothing important is being
removed, and if youre even slightly unsure, just look it up. be *very* attentive if your package
manager asks you to do something /unusual/, such as asking you to type "yes do as i say!" to
continue (linus!). over time, you will learn what is important and whats not, so dont worry, you
wont be stuck looking things up for very long, it just comes with time.

** be careful with third-party packages

sometimes, youll need something that isnt available in your distros official repo. in these cases,
youll typically want to either add a third-party repository (like a ppa on ubuntu or an overlay on
gentoo) or use a third-party source (such as the aur on arch). this is incredibly valuable, but it
should be used carefully.

a third party package:
- isnt checked by distro maintainers
- can conflict with or replace official packages, leading to issues updating
- can be outdated or unmaintained (security worry)
- can, in very rare cases, just be malicious (google: "aur incident")

so, make sure you check the official repos or [[*flatpak and appimage][flatpak]][fn:flatpak] for the
package first.

*tip*: remove third-party repos you dont use anymore

[fn:glibc] glibc is gnus c standard library implementation, if it were removed (assuming your distro
doesnt use musl) nothing will run correctly and you will need to rescue your os from a live usb. so
dont remove it unless you want a challenge

[fn:flatpak] flatpak is also third-party, it just wont conflict with system packages

* flatpak and appimage
ill admit i dont have much experience with flatpak or appimage, so itll be better you do your own
research here. there are some points for each that i can talk about.

*flatpak*:
- you dont need sudo to install them (flatpak asks for your password itself, or use =--user= to
  install just for your user)
- apps share common "runtimes" instead of system libraries, so they wont conflict with system
  packages. (this is also why your first flatpak is a big download and the rest are smaller)
- apps are sandboxed, but each app chooses its own permissions, and some ask for access to your
  whole home folder. install [[https://flathub.org/apps/com.github.tchx84.Flatseal][flatseal]] to
  check and change them
- install with =flatpak install flathub org.example.App=, update with =flatpak update= (your app
  store might already be doing this for you)

*appimage*:
- an appimage needs the executable bit set before it can run. =chmod +x whatever.AppImage=
- it bundles almost everything it needs. if one wont start, you might be missing =libfuse2=
- this is as close as youll get to the windows experience. appimages arent sandboxed and dont auto
  update, so only download them from the projects official site

* backups
youve heard the usual [[https://en.wikipedia.org/wiki/Backup][3-2-1 advice]] many times so ill spare
that, what is linux specific things you should backup.

** what to backup

your home folder covers most of it, but some important stuff lives outside of it:

- =/etc=: this is where system config is. fstab, network settings, third-party repos
- a list of your installed packages
  - pacman: =pacman -Qqe > pkglist.txt=
  - apt: =apt-mark showmanual > pkglist.txt=
  - dnf: =dnf repoquery --userinstalled > pkglist.txt=
  - zypper: im actually not sure, so look it up
  - portage: backup =/var/lib/portage/world= and everything in =/etc/portage=
  - flatpak: =flatpak list --app --columns=application > flatpaks.txt=
- your kernel config (=/usr/src/linux/.config=) if you compile your own. *you do not want to redo
  that from scratch*
- some of =/var/lib=: vms (=/var/lib/libvirt/images=), docker volumes (=/var/lib/docker/volumes=),
  databases. if you dont know what these are, you probably dont have any
- =/root= and =/var/spool/cron= (if you dont know what this is it doesnt apply to you)

** what not to backup

some stuff in home is big and useless to keep around:

- =~/.cache=: its literally cache
- =~/.local/share/Trash=: ...
- =~/.var/app/*/cache=: flatpak app caches. *keep the rest of* =~/.var/app= *though*, thats where
  flatpak apps keep their settings and data
- steam games (=~/.local/share/Steam/steamapps/common=): theyre huge and you can just redownload
  them[fn:steamsaves]. (unless youre still on vdsl, fuck you iinet!)
- anything you can rebuild, like =node_modules=, or build folders

[fn:steamsaves] most games use steam cloud for saves, but not all of them, so check


** mistakes to avoid

- hidden files: =cp -r ~/* /backup= skips hidden files. use =rsync -aHAX ~/ /backup/= or some other
  tool. (or just backup hidden files manually)
- if you copy to a fat32 or exfat usb, you lose permissions, ownership and symlinks,use a linux
  native filesystem
- secrets: =~/.ssh= and =~/.gnupg= are in home, so they get backed up too. that means either exclude
  them and back them up separately and encrypted, or encrypt your whole backup
- snapshots arent backups[fn:snapshot]

[fn:snapshot] theyre good for system rollbacks not for keeping data safe. also, timeshift skips your
home folder by default

=man=

this command is an interface for manual pages, typing =man foo= will bring up the manual page for
=foo=. this is good because the information there will (usually) be specific to the exact version of
the software you have installed, though it is quite dense and assumes you already know what youre
doing a lot of the time

* how to ask for help
now that you know where to find help, heres the information you need to include:

- your setup: distro and version, desktop environment, wayland or x11, kernel (uname -r), and
  hardware if its relevant (especially the GPU). =inxi -Fxz= gives you most of this in one go.
- what you were trying to do
- the exact error message copied as text. *do not upload a phone photo of your monitor*
- relevant logs (get kernel logs with =dmesg=, boot logs with =journalctl -b= (this boot),
  =journalctl -b -1= (previous boot). see [[*not every distro uses systemd][not every distro uses
  systemd]])
- what you already tried

now that youve got the relevant information ready, heres what to do:

- [[https://dontasktoask.com/][dont ask to ask]]
- [[https://xyproblem.info/][ask about the real goal]]
- stay there to answer questions and [[https://xkcd.com/979/][let people know when its resolved and
  what fixed it]]
- be patient and polite
- *ask about commands you dont understand*
- *again, ask about commands you dont understand*

* not every distro uses systemd
most guides you find online assume systemd, but its not the only init. if a guide tells you to run
=systemctl= and you get "command not found", youre probably on one of these:

- mx linux, antix, devuan: sysvinit
- gentoo, alpine, artix: openrc (artix also offers runit, dinit, s6)
- void: runit
- youre a legend: [[https://github.com/noahburchell/ninit][ninit]]
  
not sure? =cat /proc/1/comm= tells you what your init is. (well, sysvinit shows as "init" so if it
says that try rc-update to see what you have)

| task            | systemd                | openrc                  | runit                             |
|-----------------+------------------------+-------------------------+-----------------------------------|
| check a service | =systemctl status foo= | =rc-service foo status= | =sv status foo=                   |
| start a service | =systemctl start foo=  | =rc-service foo start=  | =sv up foo=                       |
| start on boot   | =systemctl enable foo= | =rc-update add foo=     | =ln -s /etc/sv/foo /var/service/= |
| logs            | =journalctl -u foo=    | usually =/var/log/=     | usually =/var/log/=               |
