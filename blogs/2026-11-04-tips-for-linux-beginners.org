* linux isnt windows
the old windows-isms of grabbing random executables off the web to install software, rebooting to
fix issues, and playing valorant, are gone. on linux, software is installed through the command line
using a package manager (see [[*package management][package management]]), through a gui app store
(if your desktop environment provides one), through flatpak, or with an appimage (see [[*flatpak and
appimage][flatpak and appimage]]).

most issues on linux do not need a reboot, and most updates dont need one either[fn:atomic]. unless
the kernel, systemd (or whatever init youre using), graphics drivers (especially nvidia), or glibc
has been updated. a reboot could also help if you genuinely dont know where to start fixing an
issue. otherwise you can just leave it running

[fn:atomic] on an atomic distro like bazzite, every system update needs a reboot, because theyre
done as images. flatpak updates dont

* recovery options you must have
breaking your system and losing your data are two very different things

- breaking your system: always recoverable, never a big deal. see
  [[file:2026-11-05-how-to-fix-your-broken-install.org][how to fix your "broken" install]]
- losing your data: not recoverable. big deal

so before anything else, you need both of these:

1. a bootable linux usb, any distro
2. backups of your data. see
   [[file:2026-11-08-tips-for-linux-beginners-extended.org::#backups][backups]]. the minimum is an
   external drive (ext4 or btrfs, not exfat) and either a backup app from your app store (deja dup,
   pika backup or kup) or this, run every so often:
   #+begin_example
   rsync -aHAX ~/ <backup folder on external drive>
   #+end_example

if a typo in a command can cause irrecoverable data loss, your setup is the problem

* the terminal isnt scary
a lot of people advise beginners to avoid the terminal at all costs. this is counterproductive, at
some point you will have to use it to fix an issue or use some tool that you want to use.

*if you can write* =/gamemode creative=, *you can write* =dnf upgrade --refresh=.

** how to use the terminal
well, you first need to open one! if you have deliberately installed a terminal emulator, i can
assume you know what its called. but for people whove never thought about it, heres a list of the
default terminal installed with each desktop environment:

- kde: konsole
- gnome: gnome terminal or ptyxis (this changes a lot so just search for terminal or console)
- xfce4: xfce4-terminal

so just open it like any other app, then you should see something that looks like either one of
these:

#+begin_example
[user@host ~]$ 
user@host:~$ 
#+end_example

(note: for this guide ill use "user" and "host" as a placeholder for your username and hostname)

this is called a prompt. the important parts of each are the =user=, =host=, =~= and =$=. (the rest
is just decoration)

- =user=: your username
- =host=: your hostname
- =~=: your current working directory
- =$=: delimiter, it marks the end of the prompt (not important, just know as your user it is "=$="
  (or =%= for zsh), but as root its "=#=")

you can type text here and itll appear just after your prompt

** learning to read commands
nobody knows every command, there are too many. so how do we tell a scary command from a safe
command? as a general rule, just look it up! we have /google/ and =man= yknow!? (note: man is
preferred in many cases) if you are told to run a command you dont understand, for example:

#+begin_example
find /lib/modules/$(uname -r) -iname 'nvidia*.ko*'
#+end_example

i think the =find= command would probably help /find/ something, but im not exactly sure. so i
should probably search for it!

although, before i google it maybe ill get more accurate information from the /man pages included
with most commands/. i can access these with the command =man=, so in this case, =man find=

im also not exactly sure what the rest of it means... =$(uname -r)= doesnt look like a directory,
maybe i should look it up! (note: if a command contains =$(something)=, it evaluates the command (in
this case =something=) inside the parentheses and uses its output as text. =uname -r= gets your
kernels version string, in my case =7.3.1-lychee=, so the command would expand to =find
/lib/modules/7.3.1-lychee -iname 'nvidia*.ko*'=)

another thing, i will be using this syntax throughout the guide and man pages do the same, so learn
this:
- =<foo>= is a placeholder
- =[foo]= is optional, or only needed on some installations
- =[foo | bar]= means use one of =foo= or =bar=, or neither if you don't need it
- ={foo | bar}= means you must use one of =foo= or =bar=

bonus tip: if the command has some word or character starting with a hyphen (like -iname, -r, -rf,
-a, -h) its probably a /flag/ that goes along with the command, so for the example above you could
look up "find command iname option" or something

bonus bonus tip: [[https://explainshell.com][explainshell.com]] and =tldr= are great resources that i explain more thoroughly in [[*how to find out what a command
 does][how to find out what a command does]], i very much recommend reading that section

** how to find out what a command does

=tldr=

this command is unlike man in that you will need to install it, but it is often more helpful for
beginners as it gives short, example-based summaries, and a full man page is sometimes overwhelming

=man=

this command is an interface for manual pages, typing =man foo= will bring up the manual page for
=foo=. this is good because the information there will (usually) be specific to the exact version of
the software you have installed, though it is quite dense and assumes you already know what youre
doing a lot of the time

[[https://explainshell.com][explainshell.com]]

i never knew about this site until recent! its great, and i wish someone told me about it sooner. it
breaks a command down piece by piece, and makes it easy to understand. the only note is that it
sometimes lags behind and may not know about a very new flag

** sudo / doas
=sudo= and =doas= are privilege elevation tools that let permitted users run commands as root or
another user. for now, your can ignore the "other user" part and just think of it as running a
command as *root*.

*who is root?* root is the user account with the user id 0, now that probably doesnt mean much to
you, so just think of it as the administrator account. certain things you will need to do require
administrator privileges, the most common example is probably installing new software. see
[[*package management][package management]]

when you run a command with =sudo= or =doas=, a prompt will appear asking you to type your password.
often, it will provide no visual feedback. this is normal, it isnt frozen, its just not showing you
whats being typed. so, to get an idea, please open your terminal and type the command =sudo echo hi=
or =doas echo hi=. (if your not sure which tool you have installed, try sudo first as its the more
common one). you should see a prompt asking for your password. type your password in, and hit enter.
if you typed your password correctly and you have the required privileges, you should see "hi". if
you run the same command, it may not ask for your password, this is becasue sudo (and doas with
persist enabled) cache your credentials so you dont have to repeatedly type your password. if you
see an error such as "user is not in the sudoers file", it means your account does not have
administrator permissions

** terminal survival
if you have used the terminal previously, you may have noticed that the ususal control c and control
v do not work. this is becasue control c has a much more important purpose of delivering sigint to
the active terminal process. what does that mean? sigint means signal interrupt. the usual effect of
this is stopping the running process. (note: you can also use this to cancel a half typed command
instead of deleting it all.) to copy something in the terminal, you have to use control shift. (*do
not* rebind copy to control c or you cant kill a process if needed). same with paste, control shift
v is required. there are more key combinations important to know:

- ctrl s: stops the terminal showing output
- ctrl q: resumes output
- ctrl z: suspends running process (fg restores it)
- ctrl \: a stronger ctrl c, delivers sigquit
- ctrl l: same as the =clear= command
- ctrl a: jump to the start of the line
- ctrl e: jump to the end of the line

*other odities*:

- q quits man / less (and most pagers, so if esc doesnt work try q)
- reset: if you =cat= a binary file and your terminal "breaks", jsut type reset and hit enter even
  if you cant see the output
- if you are stuck in vim: =esc :wq= saves and quits, =esc :q!= quits without saving

* dont lose your data
:PROPERTIES:
:CUSTOM_ID: dont-lose-your-data
:END:
there are certain commands to pay *extra* attention to

=sudo / doas, rm, dd, curl | *=

=sudo / doas=: these commands were covered in [[*sudo / doas][sudo / doas]]. but i only covered how to use them, not
the places where it becomes a problem. never run a gui app as root, and if a command doesnt work,
running it with sudo often will not help unless the command genuinely needs root (such as
installing/removing packages). if you happen to run something like =sudo mkdir ./<dir>=, you will
later run into issues where you cannot make files in it. that is because the directory is owned by
root and not your user. this can be resolved with ={sudo | doas} chown -R "$USER": ./<dir>=

=rm=: this command doesnt send something to the trash, it permanently deletes it and there is no
undo. the most common failure is most often not =rm -rf /= or something like that, but =rm -rf
$DIR/*=. =$DIR= should expand to =/home/user/some/trash=, but if it has been unset, it will expand
to "" and the command =rm -rf /*= will run. always wrap variables like this: =rm -rf "${DIR:?}"/*=.
(you might know that modern =rm= will block =rm -rf /= and you need the =--no-preserve-root= flag,
this is different becasuse =*= expands to all directories in root, which isnt protected)

=dd=: this command writes data somewhere, youll often see:

#+begin_example
{sudo | doas} dd if=<image>.iso of=/dev/sdX bs=4M status=progress conv=fsync
#+end_example

this is not inherently unsafe, its actually the standard way to create a bootable usb. it becomes
dangerous if =of=/dev/sdX= is the wrong location. luckily there is a small habit that makes it very
safe, always run =lsblk= before running =dd=. =lsblk= will show you all of the drives connected to
your computer, making it easy to determine the correct one. also, usually you want dd to target the
whole disk, so use =/dev/sdX= instead of =/dev/sdXY=

*tip*: if you cant tell which device is your usb, run =lsblk=, unplug it, run =lsblk= again, then
plug it back in and run =lsblk= a third time. it will have dissapeared and came back

but just so you know, if the location you typed (for example =/dev/sda=) is your boot drive[fn:nvme]
or a drive with your stuff on it, depending on the size of the disk image, youll overwrite:

1. the protective mbr
2. the primary gpt header and partition table[fn:gpt]
3. the entire efi system partition (if its at the start of the drive)
4. the beginning of the next partition, and its superblock
5. if the input never ends (=if=/dev/zero=), then literally everything

*so always double check its correct with* =lsblk=

=curl https://example.com/example.sh | bash= or the more evil version =curl
https://example.com/example.sh | sudo bash=: these commands download a script from that site and
execute it immediately without showing you what its doing. never do this blindly. if a site wants
you to install their software like this, first make *sure* the site is trustworthy, then download it
alone (=curl -LO https://example.com/example.sh=), then use =ls= to check the filename, then with
that information run =less ./example.sh= to review it, then you can run it by first making it
executable (=chmod +x ./example.sh=), and executing it like so: =./example.sh=

*> vs >>*

i dont want to go too much into teaching shell, but this one difference is worth a note. these are
redirection operators, as an example: =echo "gentoo" > gentoo.txt= will do this[fn:cat]:

#+begin_example
noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ % 
#+end_example

now, lets look at what =>>= will do:

#+begin_example
noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ % echo "gentoo" >> gentoo.txt 
noah@lychee ~ % cat gentoo.txt             
gentoo
gentoo
noah@lychee ~ % 
#+end_example

now, lets use =>= again on the same file:

#+begin_example
noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ % echo "gentoo" >> gentoo.txt 
noah@lychee ~ % cat gentoo.txt             
gentoo
gentoo
noah@lychee ~ % echo "gentoo" > gentoo.txt 
noah@lychee ~ % cat gentoo.txt            
gentoo
noah@lychee ~ % 
#+end_example

notice the difference here, =>= will truncate the file[fn:truncate] and *replace* it with what its
given. =>>= on the other hand will append to the file, *not* overwriting the content. (if there is
no file, then they act the same for all intents and purposes)

i have lost 12h of log data from this very difference >:(

[fn:nvme] on a modern device with an nvme drive, =/dev/nvme0n1= is probably your boot drive

[fn:gpt] gpt keeps a backup header at the end of the disk, so the partition table can sometimes be
recovered

[fn:cat] the command =cat= (short for (con)catenate) is a very common command for writing the
content of a file or input stream to standard output. echo writes its arguments to standard output

[fn:truncate] truncation happens prior to the command executing, so =sort foo.txt > foo.txt= will
leave you with an empty file. in this case =sort -o foo.txt foo.txt= is correct

* package management
:PROPERTIES:
:CUSTOM_ID: package-management
:END:
the most common way to install software on linux is through the package manager. common package
managers include: apt, dnf, pacman, zypper and portage. (note: for alternatives such as flatpak and
appimage, see [[*flatpak and appimage][flatpak and appimage]]). to communicate with these package
managers, you will use the terminal, here are examples for each of the package managers mentioned:

** apt

- installing a package: ={sudo | doas} apt install <package>=
- removing a package: ={sudo | doas} apt remove <package>= (or ={sudo | doas} apt purge <package>=
  to also delete config files)
- syncing repos: ={sudo | doas} apt update=
- updating everything: ={sudo | doas} apt upgrade=[fn:aptfull]
- searching for a package: =apt search <package>=

[fn:aptfull] =apt upgrade= wont remove packages, you may need ={sudo | doas} apt full-upgrade=
occasionally


** dnf

- installing a package: ={sudo | doas} dnf install <package>=
- removing a package: ={sudo | doas} dnf remove <package>=
- syncing repos: ={sudo | doas} dnf makecache= (dnf usually does this automatically)
- updating everything: ={sudo | doas} dnf upgrade=
- searching for a package: =dnf search <package>=

** pacman

- installing a package: ={sudo | doas} pacman -S <package>=
- removing a package: ={sudo | doas} pacman -R <package>= (or ={sudo | doas} pacman -Rns <package>=
  to also remove unneeded dependencies and config files)
- syncing repos + updating everything: ={sudo | doas} pacman -Syu=[fn:partial]
- searching for a package: =pacman -Ss <package>=

[fn:partial] never use ={sudo | doas} pacman -Sy <package>=, partial upgrades are unsupported


** zypper

- installing a package: ={sudo | doas} zypper install <package>=
- removing a package: ={sudo | doas} zypper remove <package>=
- syncing repos: ={sudo | doas} zypper refresh=
- updating everything: ={sudo | doas} zypper update= (on tumbleweed use ={sudo | doas} zypper dup=
  instead)
- searching for a package: =zypper search <package>=

** portage

- installing a package: ={sudo | doas} emerge -a <package>=
- removing a package: ={sudo | doas} emerge --deselect <package>= then ={sudo | doas} emerge
  --depclean=
- syncing repos: ={sudo | doas} emerge --sync=
- updating everything: ={sudo | doas} emerge -auDN @world=
- searching for a package: =emerge --search <package>=

if youre unsure which package manager came with your distro, you can use the command =command -v apt
dnf pacman zypper emerge=, and the one that returns a path is the one you have

now that you know how to use it, its important to know what youre doing and why it is this way.
briefly, your distros maintainers have a "repo" (repository) that is pretty much a sort of database
of packages. it contains the package and metadata for each one that is used when you install that
package. this may include dependencies and packages its incompatible with. what is a dependency? its
/another/ package that the package needs to function correctly. so when you ask the package manager
to install a package, it may install a few packages alongside it if it depends on them. also, your
package manager will most likely verify the integrity of the package and that it came from a
trustworthy source after it downloads it (one of the many reasons this approach is far superior to
the windows approach). "syncing" just means updating the database.

** dont delete your desktop

you may have seen that... situation linus tech tips was in when he deleted his desktop using pop os.
this was caused by a packaging mistake with steam, but linus could have avoided this, and you can too,
so heres how:

just listen to your package manager! it sounds simple, of course, but many people tend to just hit
yes on autopilot. this is normal, but you should avoid this behavior as the output of your package
manager is *not* useless monospace text, its telling you *exactly* what it is going to do! now, you
might mention that you wouldnt know removing, say, glibc[fn:glibc] was any different to removing
libcaca, thats reasonable. so the best advice i can give you is to research anything youre unsure
about. scan the package managers output for keywords like "desktop" (gnome-desktop, plasma-desktop),
"system", "wayland", "xorg", "mesa", "base", "systemd" to make sure nothing important is being
removed, and if youre even slightly unsure, just look it up. be *very* attentive if your package
manager asks you to do something /unusual/, such as asking you to type "yes do as i say!" to
continue (linus!). over time, you will learn what is important and whats not, so dont worry, you
wont be stuck looking things up for very long, it just comes with time.

** be careful with third-party packages

sometimes, youll need something that isnt available in your distros official repo. in these cases,
youll typically want to either add a third-party repository (like a ppa on ubuntu or an overlay on
gentoo) or use a third-party source (such as the aur on arch). this is incredibly valuable, but it
should be used carefully.

a third party package:
- isnt checked by distro maintainers
- can conflict with or replace official packages, leading to issues updating
- can be outdated or unmaintained (security worry)
- can, in very rare cases, just be malicious (google: "aur incident")

so, make sure you check the official repos or [[*flatpak and appimage][flatpak]][fn:flatpak] for the
package first.

*tip*: remove third-party repos you dont use anymore

[fn:glibc] glibc is gnus c standard library implementation, if it were removed (assuming your distro
doesnt use musl) nothing will run correctly and you will need to rescue your os from a live usb. so
dont remove it unless you want a challenge

[fn:flatpak] flatpak is also third-party, it just wont conflict with system packages

* flatpak and appimage
:PROPERTIES:
:CUSTOM_ID: flatpak-and-appimage
:END:
ill admit i dont have much experience with flatpak or appimage, so itll be better you do your own
research here. there are some points for each that i can talk about.

*flatpak*:
- you dont need sudo to install them (flatpak asks for your password itself, or use =--user= to
  install just for your user)
- apps share common "runtimes" instead of system libraries, so they wont conflict with system
  packages. (this is also why your first flatpak is a big download and the rest are smaller)
- apps are sandboxed, but each app chooses its own permissions, and some ask for access to your
  whole home folder. install [[https://flathub.org/apps/com.github.tchx84.Flatseal][flatseal]] to
  check and change them
- install with =flatpak install flathub org.example.App=, update with =flatpak update= (your app
  store might already be doing this for you)
- on some distros, flathub isnt configured by default, so you need to add the remote repo with
  =flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo=
  (unless the link changed since, check online for recent updates)
- to remove unused deps(runtimes), use =flatpak uninstall --unused=

*appimage*:
- an appimage needs the executable bit set before it can run. =chmod +x <app>.AppImage=
- it bundles almost everything it needs. if one wont start, you might be missing =libfuse2=
- this is as close as youll get to the windows experience. appimages arent sandboxed and dont auto
  update, so only download them from the projects official site

* how to ask for help
now that you know where to find help, heres the information you need to include:

- your setup: distro and version, desktop environment, wayland or x11, kernel (uname -r), and

- what you were trying to do
- the exact error message copied as text. *do not upload a phone photo of your monitor*
- relevant logs (get kernel logs with =[sudo | doas] dmesg=, boot logs with =[sudo | doas]
  journalctl -b= (this boot), =[sudo | doas] journalctl -b -1= (previous boot). see

  runs on any distro without being installed
- atomic distro :: a distro that updates the whole system as one image instead of package by
  package. every system update takes effect on the next reboot. bazzite and fedora silverblue are
  examples
- aur :: the arch user repository. user submitted build scripts for arch, not checked by the
  maintainers
- block device :: a device file that exposes storage in blocks, such as a disk or a partition. found
  in =/dev=
- bootloader :: the program the firmware runs to load the kernel. grub or systemd-boot are common
- daemon :: a program that runs in the background with no terminal attached, usually started by the
  init system. sshd and keyd are daemons
- dependency :: a package that another package needs to function. the package manager installs
  dependencies alongside the package that requires them
- desktop environment :: the collection of programms that together provide a window manager, panel,
  settings, file manager and default apps. kde plasma, gnome and xfce are examples
- device file :: a file under =/dev= that represents a piece of hardware or a kernel interface.
  reading and writing the file reads and writes the device
- distro :: a linux distribution. the linux kernel packaged with a package manager, an init system
  and a selection of software, maintained and released as one operating system
- dotfile :: a file or directory whose name starts with a period, also called a hidden file. =ls=
  does not show it without =-a=. most user configuration lives in dotfiles
- efi system partition :: a fat32 (or fat16/fat12 as per uefi standard) partition the firmware reads
  bootloaders from. required to boot a uefi machine. usually the first partition on the boot drive
  (it doesnt have to be, and you can have two on the same drive lol)
- environment variable :: a named value held by a process and inherited by any processes it starts.
  =$HOME=, =$PATH= and =$USER= are examples
- executable bit :: a file permission that allows the file to be run as a program. set with =chmod
  +x=
- filesystem :: the format that organizes files on a partition. ext4, btrfs and xfs are linux
  native, fat32, exfat and ntfs are not
- flag :: an argument that changes how a command behaves, written with a leading hyphen such as =-r=
  or =--help=. also called an option
- flatpak :: a package format that installs apps into a sandbox with their own runtime libraries,
  independent of the distros packages. flathub is the main flatpak repository
- gpt :: guid partition table. the modern partition table format. keeps a primary header at the
  start of the disk and a backup at the end
- home directory :: the directory a user owns for their files and configuration, usually
  =/home/user=. =~= expands to it
- hostname :: the name of the machine
- init :: the first process the kernel starts, pid 1. it starts every other service and adopts
  orphaned processes. systemd, openrc, ninit and sysvinit are init systems
- inode :: the on-disk record of a files metadata and the location of its data. a filename is a
  directory entry that points at an inode
- kernel :: the "manager" of processes, and the interface for userspace to hardware and other stuff.
  sometimes refered to as the "core", but i dont really like that framing, since its a part of every
  process (mapped into its virtual adress space) (well, not since whichever cpu vulnerability that i
  forgot the name of) but lets not overcomplicate this actually, just look it up it needs a whole
  nother article to explain 50% of it!
- kernel module :: kernel code loaded at runtime, usually a driver. stored under
  =/lib/modules/<version>= as =.ko= files
- live usb :: a usb drive that boots a complete linux system without installing anything. often used
  to install a distro and to repair one that no longer boots
- man page :: manual page. read with =man=
- mbr :: master boot record. the first sector of a disk, holding a legacy partition table and some
  boot code
- mesa :: the open source implementation of opengl and vulkan. the usespace half of the graphics
  drivers for amd and intel gpus
- mount :: to attach a filesystem to a directory so its contents are reachable there. the directory
  is the mount point
- musl :: a small c standard library used in place of glibc by alpine and some other distros
- nvme :: a storage interface for ssds attached over pcie. the drives appear as =/dev/nvme0n1=,
  their partitions as =/dev/nvme0n1p1= (note: the =n1= means namespace 1, its an enterprise thing)
- overlay :: a third-party package repository on gentoo
- package :: a software component in the format the package manager installs. holds the files plus
  metadata such as version, dependencies and conflicts
- package manager :: the program that installs, removes and updates packages from repositories and
  tracks what is installed. apt, dnf, pacman, zypper and portage are examples
- pager :: a program that shows text one screen at a time. =less= is the usual one
- partition :: a region of a disk listed in the partition table. holds one filesystem or is used as
  swap
- pid :: process id. the number the kernel assigns to each running process
- pipe :: the =|= operator. connects the standard output of one command to the standard input of the
  next
- ppa :: personal package archive. a third-party repository for ubuntu
- process :: a running program. has a pid, a user, a working directory and environment variables
- prompt :: the text the shell prints when it is waiting for a command
- redirection :: sending a commands output to a file, or reading its input from one. =>= writes the
  file, =>>= appends to it, =<= reads from it
- repository :: a server holding packages and an index of their metadata. the package manager
  downloads from the repositories configured for the distro. abbreviated to repo
- root :: the user with user id 0. every permission check passes for root. also the top of the
  filesystem tree, =/=, which every path starts from
- sandbox :: a restricted environment that limits what a program can reach, such as files, devices
  and the network
- service :: a program the init system starts and (might) supervise(s), usually a daemon
- shell :: the program that reads commands from the terminal and runs them. bash is the default on
  most distros
- signal :: a notification the kernel delivers to a process
- snapshot :: a copy of a filesystems state at a point in time, kept on the same disk. used for
  rollback
- standard output :: the stream a program writes its normal output to, shown in the terminal unless
  redirected. standard error carries its error messages, standard input is what it reads (note:
  =/dev/stdout= and that are actually symlinks to =/proc/self/fd/x=, the more you know)
- sudo :: runs a command as another user, root by default, after checking that the calling user is
  permitted in =/etc/sudoers=. doas is a smaller equivalent
- superblock :: the record at the start of a filesystem describing its layout, size and state. the
  filesystem cannot be mounted without it
- symlink :: symbolic link. a file that holds the path to another file. most operations follow it to
  the target
- sync :: downloading the latest repository index so the package manager knows the current package
  versions
- systemd :: the init system used by most distros. also provides journald for logs, logind,
  networkd, timers and more
- terminal emulator :: a graphical program that displays a terminal for a shell to run in. like
  konsole, gnome terminal and foot
- third-party repository :: a repository not run by the distro and added by the user. ppas, overlays
  and the aur are examples
- uid :: user id. the number that identifies a user to the kernel. root is 0
- userspace :: everything that is not the kernel: programs, libraries, the shell and the desktop
- wayland :: the current display protocol, the way programs draw windows and receive input. it is
  replacing x11 (for the better!)
- wildcard :: a character the shell expands to matching filenames. =*= matches any string, =?=
  matches one character. also called a glob
- wine :: a compatibility layer that runs windows programs on linux. proton is valves version of it
  for steam
- working directory :: the directory a process resolves relative paths against. =cd= changes it,
  =pwd= prints it, the prompt shows it
- x11 :: the x window system, the display protocol used before wayland. xorg is its server
