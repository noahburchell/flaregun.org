* linux isnt windows
the old windows-isms of grabbing random executables off the web to
install software, or rebooting to fix issues, or playing valorant,
are gone. on linux, software is installed through the command line
using a package manager, or through a gui app store (if your
desktop environment provides one). most issues on linux do not need
a reboot and most updates dont need one either. unless the kernel
has been updated or you genuinely dont know where to start fixing an
issue. otherwise you can just leave it running

* the terminal isnt scary
/...if you learn which commands are/

a lot of people advise beginners to avoid the terminal at all costs.
this is counterproductive, at some point you will have to use it to
fix an issue or use some tool that you want to use. if you can write
=/gamemode creative=, you can write =dnf upgrade --refresh=.
so how do you tell a scary command from a safe command? as a
general rule, just look it up! we have /google/ and =man= yknow!?
(note: man is prefered in many cases) if you are told to run a command
you dont understand, for example:

=find /lib/modules/$(uname -r) -iname 'nvidia*.ko*'=

there are certain commands to pay *extra* attention to

=sudo / doas, rm, dd, curl | *=

=sudo / doas=: any commands ran with either of these prefixes can
do... anything.

=rm=: this command doesnt send somethign to the trash, it permenantly
deletes it and there is not undo

=dd=: this command writes data somewhere, youll often see
=dd if=/some/diskimage.iso of=/dev/sdX bs=4M status=progress conv=fsync=.
this is not inherently unsafe, its actually the standard way to create a
bootable usb. it becomes dangerous if =of=/dev/sdX= is the wrong location.
if the location you typed (for example =/dev/sda=) is your boot drive,
depending on the size of the disk image, youll overwrite:

1. the protective mbr
2. the primary gpt header and partition table
3. the entire efi system partition
4. the beginning of the next partition, and its superblock
5. if the input never ends (=if=/dev/zero=), then literally everything

*always double check its correct with* =lsblk=

=curl https://example.com/example.sh | bash= or the more evil version
=curl https://example.com/example.sh | sudo bash=: these commands download
a script from that site and execute it immediately without showing you what
theyre doing. never do this. if a site wants you to install their
software like this, first make sure the site is trustworthy, then download
it alone (=curl -O https://example.com/example.sh=), then use =ls= to check
the filename, then with that information run =less ./example.sh= to review
it, then you can run it by first making it executable (=chmod +x ./example.sh=),
and executing it like so: =./example.sh=
