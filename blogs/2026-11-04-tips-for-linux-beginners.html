1. how to use this guide

if youre a begginner and want to learn linux, read all the sections

  • this guide is aimed at beginners, but some sections require willingness to learn
  • you dont have to read top down, jump to the sections you want to learn about
  • there may be words you dont understand and arent explained, you are encouraged to look things up. though, there is a glossary you can check out first.

2. linux isnt windows

the old windows-isms of grabbing random executables off the web to install software, rebooting to fix issues, and playing valorant, are gone. on linux, software is installed through the command line using a package manager (see package management), through a gui app store (if your desktop environment provides one), through flatpak, or with an appimage (see flatpak and appimage).

most issues on linux do not need a reboot, and most updates dont need one either1. unless the kernel, systemd (or whatever init youre using), graphics drivers (especially nvidia), or glibc has been updated. a reboot could also help if you genuinely dont know where to start fixing an issue. otherwise you can just leave it running

3. the terminal isnt scary

a lot of people advise beginners to avoid the terminal at all costs. this is counterproductive, at some point you will have to use it to fix an issue or use some tool that you want to use.

if you can write /gamemode creative, you can write dnf upgrade --refresh.

3.1. how to use the terminal

well, you first need to open one! if you have deliberately installed a terminal emulator, i can assume you know what its called. but for people whove never thought about it, heres a list of the default terminal installed with each desktop environment:

  • kde: konsole
  • gnome: gnome terminal or ptyxis (this changes a lot so just search for terminal or console)
  • xfce4: xfce4-terminal

so just open it like any other app, then you should see something that looks like either one of these: 

[user@host ~]$ 
user@host:~$

(note: for this guide ill use "user" and "host" as a placeholder for your username and hostname)

this is called a prompt. the important parts of each are the user, host, ~ and $. (the rest is just decoration)

  • user: your username
  • host: your hostname
  • ~: your current working directory
  • $: delimiter, it marks the end of the prompt (not important, just know as your user it is "$" (or % for zsh), but as root its "#")

you can type text here and itll appear just after your prompt. so now lets go over some important commands

3.2. ls, cd

ls will list everything in your current working directory. usually, when you open the terminal this will be /home/user (~ is a shortcut for /home/user). so if you run ls right now, you may see "Documents", "Downloads", etc.

cd will move you into a directory. lets say you just ran ls, and you want to go to documents: since ls listed "Documents" in your current directory, you can type cd Documents to go there

3.3. "." ".."

. is your current directory. so if you run ls and see "Documents", cd ./Documents is equivelant to cd Documents

.. is the parent directory. if you just ran cd Documents, you will be in /home/user/Documents. so running cd ../ will move you back to ~

3.4. sudo / doas

sudo and doas are privilege elevation tools that let permitted users run commands as root or another user. for now, your can ignore the "other user" part and just think of it as running a command as root.

who is root? root is the user account with the user id 0, now that probably doesnt mean much to you, so just think of it as the administrator account. certain things you will need to do require administrator privileges, the most common example is probably installing new software. see package management

when you run a command with sudo or doas, a prompt will appear asking you to type your password. often, it will provide no visual feedback. this is normal, it isnt frozen, its just not showing you whats being typed. so, to get an idea, please open your terminal and type the command sudo echo hi or doas echo hi. (if your not sure which tool you have installed, try sudo first as its the more common one). you should see a prompt asking for your password. type your password in, and hit enter. if you typed your password correctly and you have the required privileges, you should see "hi". if you run the same command, it may not ask for your password, this is becasue sudo (and doas with persist enabled) cache your credentials so you dont have to repeatedly type your password. if you see an error such as "user is not in the sudoers file", it means your account does not have administrator permissions

3.5. file manipulation

this may be the second most common use of the terminal next to package management. so its important to know how to view, create, move, and edit files without opening a file manager. im going to assume nano for this guide, if you installed vim or mg, ill assume you know how to use them

i dont want to type this super long filename:

luckily, you have tab completion. start typing a file or directory name then press tab and the shell fills in the rest (if what your looking for exists). hit tab twice to see every option.

spaces in filenames? cat my file.txt looks for a file called "my" and one called "file.txt". quote it like cat "my file.txt" or escape the space cat my\ file.txt. tab completion does this for you

also, most linux native filesystems is case sensitive so Documents and documents are two different directories

looking at files:

  • cat foo.txt: prints the whole file
  • less foo.txt: opens the file in a pager you can scroll through. q to quit, /word to search, n for the next match
  • ls -l: lists files with their size, owner, permissions and modification date. ls -a also shows hidden files, ls -la does both
  • file foo: tells you what file a file is

making, copying, moving:

  • mkdir foo: makes a directory. mkdir -p foo/bar/baz makes all of those at once if they dont exist
  • touch foo.txt: makes an empty file
  • cp foo.txt bar.txt: copies a file foo.txt to bar.txt
  • mv foo.txt bar.txt: moves a file. this is also how you rename things

note that cp and mv will overwrite an existing file with the same name without asking. add -i if you want to be asked

another difference: mv (on the same drive) is instant and all or nothing, the file either has the old content or the new content. cp rewrites the destination bit by bit, so if its interrupted or something reads it mid-copy, you get a half-written file2. this is why the safe way to replace a file is to write the new version somewhere else and mv it over the top

when does cp or rsync copy only the contents of the directory into the new directory versus copying the whole directory into the directory making it a subdirectory of the new directory? honestly, i dont fucking know. it seems to flip a coin.

deleting:

rm deletes files, rm -r deletes directories, and none of it goes to the trash. i covered this in dont lose your data. if you want a terminal command that actually uses the trash, gio trash foo probably will work, or install trash-cli and use trash-put foo

editing with nano:

nano foo.txt opens the file (or creates it). the bottom of the screen shows the shortcuts. ^ means ctrl and M- means alt. here are common ones:

  • ctrl+o: save
  • ctrl+x: exit
  • ctrl+w: search
  • ctrl+k: cut the current line, ctrl+u to paste it back
  • alt+u: undo
  • ctrl+g: help

if the file is owned by root (most of /etc), you will need sudo nano /etc/foo3

wildcards:

you will see * in a lot of commands. the shell expands it to "every file that matches", so ls *.txt lists every file ending in .txt and cp ~/Pictures/*.png /backup/ copies every png. this is useful and also how rm -rf $DIR/* goes wrong (see dont lose your data)

3.6. terminal survival

if you have used the terminal previously, you may have noticed that the ususal control c and control v do not work. this is becasue control c has a much more important purpose of delivering sigint to the active terminal process. what does that mean? sigint means signal interrupt. the usual effect of this is stopping the running process. (note: you can also use this to cancel a half typed command instead of deleting it all.) to copy something in the terminal, you have to use control shift. (do not rebind copy to control c or you cant kill a process if needed). same with paste, control shift v is required. there are more key combinations important to know:

  • ctrl s: stops the terminal showing output
  • ctrl q: resumes output
  • ctrl z: suspends running process (fg restores it)
  • ctrl \: a stronger ctrl c, delivers sigquit
  • ctrl l: same as the clear command
  • ctrl a: jump to the start of the line
  • ctrl e: jump to the end of the line

other odities:

  • q quits man / less (most pagers, if esc doesnt work try q)
  • reset: if you cat a binary file and your terminal "breaks", jsut type reset and hit enter even if you cant see the output
  • if you are stuck in vim: :wq saves and quits, :q! quits without saving

3.7. learning to read commands

nobody knows every command, there are too many. so how do we tell a scary command from a safe command? as a general rule, just look it up! we have google and man yknow!? (note: man is preferred in many cases) if you are told to run a command you dont understand, for example: 

find /lib/modules/$(uname -r) -iname 'nvidia*.ko*'

i think the find command would probably help find something, but im not exactly sure. so i should probably search for it!

although, before i google it maybe ill get more accurate information from the man pages included with most commands. i can access these with the command man, so in this case, man find

im also not exactly sure what the rest of it means… $(uname -r) doesnt look like a directory, maybe i should look it up! (note: if a command contains $(something), it evaluates the command (in this case something) inside the parentheses and uses its output as text. uname -r gets your kernels version string, in my case 7.3.1-lychee, so the command would expand to find /lib/modules/7.3.1-lychee -iname 'nvidia*.ko*')

bonus tip: if the command has some word or character starting with a hyphen (like -iname, -r, -rf, -a, -h) its probably a flag that goes along with the command, so for the example above you could look up "find command iname option" or something

bonus bonus tip: explainshell.com and tldr are great resources that i explain more thoroughly in where to find help, i very much recommend reading that section

4. dont lose your data

there are certain commands to pay extra attention to

sudo / doas, rm, dd, curl | *

sudo / doas: these commands were covered in sudo / doas. but i only covered how to use them, not the places where it becomes a problem. never run a gui app as root, and if a command doesnt work, running it with sudo often will not help unless the command genuinely needs root. if you happen to run something like sudo mkdir ./foo, you will later run into issues where you cannot make files in it. that is because the directory is owned by root and not your user. this can be resolved with sudo chown -R "$USER": ./foo

rm: this command doesnt send something to the trash, it permanently deletes it and there is no undo. the most common failure is most often not rm -rf / or something like that, but rm -rf $DIR/*. $DIR should expand to /home/user/some/trash, but if it has been unset, it will expand to "" and the command rm -rf /* will run. always wrap variables like this: rm -rf "${DIR:?}"/*. (you might know that modern rm will block rm -rf / and you need the --no-preserve-root flag, this is different becasuse * expands to all directories in root, which isnt protected)

dd: this command writes data somewhere, youll often see: 

dd if=/some/diskimage.iso of=/dev/sdX bs=4M status=progress conv=fsync

this is not inherently unsafe, its actually the standard way to create a bootable usb. it becomes dangerous if of=/dev/sdX is the wrong location. luckily there is a small habit that makes it very safe, always run lsblk before running dd. lsblk will show you all of the drives connected to your computer, making it easy to determine the correct one. also, usually you want dd to target the whole disk, so use /dev/sdX instead of /dev/sdXY

tip: if you cant tell which device is your usb, run lsblk, unplug it, run lsblk again, then plug it back in and run lsblk a third time. it will have dissapeared and came back

but just so you know, if the location you typed (for example /dev/sda) is your boot drive4 or a drive with your stuff on it, depending on the size of the disk image, youll overwrite:

  1. the protective mbr
  2. the primary gpt header and partition table5
  3. the entire efi system partition (if its at the start of the drive)
  4. the beginning of the next partition, and its superblock
  5. if the input never ends (if=/dev/zero), then literally everything

so always double check its correct with lsblk

curl https://example.com/example.sh | bash or the more evil version curl https://example.com/example.sh | sudo bash: these commands download a script from that site and execute it immediately without showing you what its doing. never do this blindly. if a site wants you to install their software like this, first make sure the site is trustworthy, then download it alone (curl -LO https://example.com/example.sh), then use ls to check the filename, then with that information run less ./example.sh to review it, then you can run it by first making it executable (chmod +x ./example.sh), and executing it like so: ./example.sh

> vs >>

i dont want to go too much into teaching shell, but this one difference is worth a note. these are redirection operators, as an example: echo "gentoo" > gentoo.txt will do this6: 

noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ %

now, lets look at what >> will do: 

noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ % echo "gentoo" >> gentoo.txt 
noah@lychee ~ % cat gentoo.txt             
gentoo
gentoo
noah@lychee ~ %

now, lets use > again on the same file: 

noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ % echo "gentoo" >> gentoo.txt 
noah@lychee ~ % cat gentoo.txt             
gentoo
gentoo
noah@lychee ~ % echo "gentoo" > gentoo.txt 
noah@lychee ~ % cat gentoo.txt            
gentoo
noah@lychee ~ %

notice the difference here, > will truncate the file7 and replace it with what its given. >> on the other hand will append to the file, not overwriting the content. (if there is no file, then they act the same for all intents and purposes)

5. you learnt windows, you can learn linux

i think its called the curse of knowledge, where you forget what it was like to not know? whatever it is, the point is that at some point you had to learn how to use windows, you had to learn how to search for an app, you learnt what a sketchy vs safe download looked like8. so you should expect to have to learn how to use linux, learn how to use the package manager (see package management) for apps, learn how your desktop works, and, dont be discouraged if you fuck something up9. youre learning!

6. package management

the most common way to install software on linux is through the package manager. common package managers include: apt, dnf, pacman, zypper and portage. (note: for alternatives such as flatpak and appimage, see flatpak and appimage). to communicate with these package managers, you will use the terminal, here are examples for each of the package managers mentioned:

6.1. apt

  • installing a package: apt install whatever
  • removing a package: apt remove whatever (or apt purge whatever to also delete config files)
  • syncing repos: apt update
  • updating everything: apt upgrade10
  • searching for a package: apt search whatever

6.2. dnf

  • installing a package: dnf install whatever
  • removing a package: dnf remove whatever
  • syncing repos: dnf makecache (dnf usually does this automatically)
  • updating everything: dnf upgrade
  • searching for a package: dnf search whatever

6.3. pacman

  • installing a package: pacman -S whatever
  • removing a package: pacman -R whatever (or pacman -Rns whatever to also remove unneeded dependencies and config files)
  • syncing repos + updating everything: pacman -Syu11
  • searching for a package: pacman -Ss whatever

6.4. zypper

  • installing a package: zypper install whatever
  • removing a package: zypper remove whatever
  • syncing repos: zypper refresh
  • updating everything: zypper update (on tumbleweed use zypper dup instead)
  • searching for a package: zypper search whatever

6.5. portage

  • installing a package: emerge -a whatever
  • removing a package: emerge -a --deselect whatever then emerge --depclean
  • syncing repos: emerge --sync
  • updating everything: emerge -auDN @world
  • searching for a package: emerge --search whatever

if youre unsure which package manager came with your distro, you can use the command which apt dnf pacman zypper emerge, and the one that returns a path is the one you have. also installing or updating packages and syncing most often requires root privileges, so make sure to run those commands with sudo or doas

now that you know how to use it, its important to know what youre doing and why it is this way. briefly, your distros maintainers have a "repo" (repository) that is pretty much a sort of database of packages. it contains the package and metadata for each one that is used when you install that package. this may include dependencies and packages its incompatible with. what is a dependency? its another package that the package needs to function correctly. so when you ask the package manager to install a package, it may install a few packages alongside it if it depends on them. also, your package manager will most likely verify the integrity of the package and that it came from a trustworthy source after it downloads it (one of the many reasons this approach is far superior to the windows approach). "syncing" just means updating the database.

6.6. dont delete your desktop

you may have seen that… situation linus was in when he deleted his desktop using pop os. this was caused by a packaging mistake with steam, but linus could have avoided this, and you can too, so heres how:

just listen to your package manager! it sounds simple, of course, but many people tend to just hit yes on autopilot. this is normal, but you should avoid this behavior as the output of your package manager is not useless monospace text, its telling you exactly what it is going to do! now, you might mention that you wouldnt know removing, say, glibc12 was any different to removing libcaca, thats reasonable. so the best advice i can give you is to research anything youre unsure about. scan the package managers output for keywords like "desktop" (gnome-desktop, plasma-desktop), "system", "wayland", "xorg", "mesa", "base", "systemd" to make sure nothing important is being removed, and if youre even slightly unsure, just look it up. be very attentive if your package manager asks you to do something unusual, such as asking you to type "yes do as i say!" to continue (linus!). over time, you will learn what is important and whats not, so dont worry, you wont be stuck looking things up for very long, it just comes with time.

6.7. be careful with third-party packages

sometimes, youll need something that isnt available in your distros official repo. in these cases, youll typically want to either add a third-party repository (like a ppa on ubuntu or an overlay on gentoo) or use a third-party source (such as the aur on arch). this is incredibly valuable, but it should be used carefully.

a third party package:

  • isnt checked by distro maintainers
  • can conflict with or replace official packages, leading to issues updating
  • can be outdated or unmaintained (security worry)
  • can, in very rare cases, just be malicious (google: "aur incident")

so, make sure you check the official repos or flatpak13 for the package first.

tip: remove third-party repos you dont use anymore

7. flatpak and appimage

ill admit i dont have much experience with flatpak or appimage, so itll be better you do your own research here. there are some points for each that i can talk about.

flatpak:

  • you dont need sudo to install them (flatpak asks for your password itself, or use --user to install just for your user)
  • apps share common "runtimes" instead of system libraries, so they wont conflict with system packages. (this is also why your first flatpak is a big download and the rest are smaller)
  • apps are sandboxed, but each app chooses its own permissions, and some ask for access to your whole home folder. install flatseal to check and change them
  • install with flatpak install flathub org.example.App, update with flatpak update (your app store might already be doing this for you)
  • on some distros, flathub isnt configured by default, so you need to add the remote repo with flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo (unless the link changed since, check online for recent updates)
  • to remove unused deps(runtimes), use flatpak uninstall --unused

appimage:

  • an appimage needs the executable bit set before it can run. chmod +x whatever.AppImage
  • it bundles almost everything it needs. if one wont start, you might be missing libfuse2
  • this is as close as youll get to the windows experience. appimages arent sandboxed and dont auto update, so only download them from the projects official site

8. finding alternative apps

i once read a reddit post about a user who was asking how to get rufus working through wine to make a bootable usb. honestly, that seems to make total sense, thats how you do it on windows, so it must be how you do it on linux. but, linux has plenty of tools that do the same thing without the trouble of trying to get it working through wine. for this case, a good gui like balena etcher works, or just dd if you dont want to install anything (see dont lose your data)

so as a rule, try reframe the question youre asking to what your trying to do. im not entirely sure how to describe this so here are some examples:

  • how do i get rufus working on linux? -> how do i make a bootable usb on linux?
  • how do i get notepad++ on linux -> how do i install emacs on (your distro)? best linux text editors?
  • how do i get paint.net working on linux? -> best linux photo editor?
  • how do i get crystaldiskinfo working on linux? -> how do i check my drives halth on linux?
  • how do i open task manager on linux? -> how do i see whats using my cpu on linux?

as a last resort, wine does work great. just make sure to try the native route first14

9. permissions

youve already seen this: sudo mkdir ./foo gave you a directory you cant write to, and an appimage wont run until chmod +x. both are permissions. "permission denied" is probably one of the most common errors youll see

also, "permissions" means three different things on linux and people mix them up:

  1. unix file permissions (this section)
  2. selinux / apparmor (see selinux and apparmor)
  3. app sandboxes like flatpak (see flatpak and appimage)

9.1. basics

every file has an owner and a group. then it has three sets of permissions for the owner, the group, and everyone else. run ls -l and look at one line 

-rw-r--r-- 1 noah noah 1234 Nov  1 00:00 foo.txt
drwxr-xr-x 2 noah noah 4096 Nov  1 00:00 Documents

the third column is the owner, the fourth is the group. the first column is the permissions themselves. so foo.txt is owned by user noah and group noah

9.2. what is -rw-r--r--

-rw-r--r-- has 1 character for the type, then 3 groups of 3 characters for perms

the first character: the file type. d directory, - regular file, l symlink, c character device, b block device, p named pipe and s socket

the next 3: the owner. r read, w write, x execute. - means no

the next 3: the group

the last 3: everyone else

  • -rw-r--r-- -> "a regular file, the owner can read and write it, everyone else can only read it".
  • drwxr-xr-x -> "a directory, the owner can do everything, everyone else can look around but not change anything"

if theres an 11th character (. or +), see selinux and apparmor

9.3. rwx is different for directories

here:

perm on a file on a directory
r read the contents list the names in it (ls)
w change it create, delete or rename things in it
x run it as a program enter it (cd) and access things in it by name

to delete a file you need w on the directory, so a read only file in a directory you own is still deletable by you. and a directory with r but no x lets you see names but not open any of them

9.4. who am i and what groups am i in

id tells you your user, your primary group and every other group youre in. groups are how you get access to things without being root. on most distros being in video gives you video card access, dialout gives you serial access (i think), docker lets you talk to docker without root (do not add yourself to docker group if you dont know the consequence16), wheel (or sudo on debian/ubuntu) is what lets you use sudo at all

add yourself to a group with sudo usermod -aG groupname "$USER". without the -a, you replace your groups instead of adding one (not good). then log out and back in, group changes dont apply to sessions that are already open process

9.5. changing permissions

chmod changes rwx

  • chmod +x script.sh: make it executable (for everyone17) (also make sure you are holding shift and dont accidentally put =x, becasuse that does this weird bs where it makes it only exectable causing a weird error that you may spend too long trying to figure out….)
  • chmod u+w foo: give the owner (u) write
  • chmod go-r secret.txt: take read away from group (g) and others (o)
  • chmod -R ...: do it recursively

guides will instead tell you chmod 755 or chmod 644. those are the same thing as numbers: r=4, w=2, x=1, add them up per set. so 7 is rwx, 6 is rw-, 5 is r-x, 4 is r--. the three digits are owner, group, other

  • 644: rw-r--r--, a normal file
  • 755: rwxr-xr-x, a script or a directory
  • 600 / 700: only you, used for secrets. ssh will actually refuse to work if ~/.ssh and the contents of it are too open

chown changes the owner and group: sudo chown user:group foo. the one youll actually use is fixing a root-owned directory: sudo chown -R "$USER": ./foo (the trailing colon means "and my primary group")

dont chmod -R 777 things. it "fixes" the error by making the file writable by every program and user on the system. find out which permission is actually missing instead

9.6. root ignores this

root passes every rw(x) check, which is why sudo "fixes" permission errors (thats the wrong fix, see dont lose your data). root doesnt ignore the execute bit on files, immutable files, read only mounted filesystems and selinux/apparmour

9.7. permission denied, but ls -l says im allowed?

in order of likelihood:

  • you just added yourself to a group and havent logged out
  • the drive is fat32/exfat/ntfs. (permissions come from mount options, see backups)
  • the partition is mounted noexec, somewhat common for /tmp and usb drives
  • the directory above it is missing x for you
  • its a flatpak and the sandbox cant see that folder. fix it in flatseal
  • selinux or apparmor (see below)

9.8. selinux and apparmor

standard permissions tell you "is this user allowed". selinux and apparmor ask "is this program allowed to touch this at all", this is called mandatory access control (mac)

do i have this?:

  • anything fedora or rhel based: selinux. getenforce prints enforcing, permissive or disabled
  • ubuntu, debian: apparmor. sudo aa-status lists the loaded profiles
  • arch, gentoo: probably neither unless you set it up
  • anything else: check! it should be easy to find if you look up your distro

if you dont have it, skip this section

common issues: you set up a web server (maybe using nhttp!), samba, game server or ssh, you move a file into its directory, ls -l says the permissions are fine, and the service still cant read it

with selinux thats because every file has a label (the 11th character . in ls -l means one is there, ls -Z shows it). a file created in /var/www gets a web label, a file moved there keeps the label from your home folder (remember, mv doesnt rewrite the file, see here2). sudo restorecon -Rv /path puts the correct labels back. to see what got denied, you can look at sudo ausearch -m avc -ts recent, or on fedora just open the setroubleshoot notification, it explains it in english (i think, its been a while)

with apparmor its per program. each (confined) program has a profile in /etc/apparmor.d/ listing what it may touch, and your path isnt there. logs show up in (sudo) dmesg | grep -i apparmor or journalctl -k | grep DENIED (with systemd). you can set one profile to complain mode (log but allow) with sudo aa-complain /path/to/program while you work out whats missing

dont turn it off (setenforce 0 / SELINUX=disabled)

it "fixes it", by removing it entirely. this is like disabling windows defender entirely becasue an app wont run, so dont do it. there is a proper permenant fix with semanage fcontext or somethign, im not going to cover that becasue i have no idea and dont use selinux. rhel docs are probably the best place to look

9.9. special perms

youll sometimes see s or t where an x should be, for example on /usr/bin/sudo and /tmp. s (setuid) on the owner slot means the program runs as its owner, t on a directory means you can only delete your own files in it

11. backups

youve heard the usual 3-2-1 advice many times so ill spare that, what is linux specific things you should backup.

11.1. what to backup

your home folder covers most of it, but some important stuff lives outside of it:

  • /etc: this is where system config is. fstab, network settings and third-party repos and the lot, treat this as somewhat sensitive tho be becasue it may contain wifi passwords and other shit. (is yours 12345678? i see you)
  • a list of your installed packages
    • pacman: pacman -Qqe > pkglist.txt
    • apt: apt-mark showmanual > pkglist.txt
    • dnf: dnf repoquery --userinstalled > pkglist.txt
    • zypper: im actually not sure, so look it up
    • portage: backup /var/lib/portage/world and everything in /etc/portage
    • flatpak: flatpak list --app --columns=application > flatpaks.txt
  • your kernel config (/usr/src/linux/.config) if you compile your own. you do not want to redo that from scratch
  • some of /var/lib: vms (/var/lib/libvirt/images), docker volumes (/var/lib/docker/volumes), databases. if you dont know what these are, you probably dont have any
  • /root and /var/spool/cron (if you dont know what this is it doesnt apply to you)

11.2. what not to backup

some stuff in home is big and useless to keep around:

  • ~/.cache: its literally cache
  • ~/.local/share/Trash: …
  • ~/.var/app/*/cache: flatpak app caches. keep the rest of ~/.var/app though, thats where flatpak apps keep their settings and data
  • steam games (~/.local/share/Steam/steamapps/common): theyre huge and you can just redownload them19. (unless youre still on vdsl, fuck you iinet!)
  • anything you can rebuild, like node_modules, or build folders

11.3. mistakes to avoid

  • hidden files: cp -r ~/* /backup skips hidden files. use rsync -aHAX ~/ /backup/ or some other tool. (or just backup hidden files manually)
  • if you copy to a fat32 or exfat usb, you lose permissions, ownership and symlinks,use a linux native filesystem
  • secrets: ~/.ssh and ~/.gnupg are in home, so they get backed up too. that means either exclude them and back them up separately and encrypted, or encrypt your whole backup
  • snapshots arent backups20

13. how to ask for help

now that you know where to find help, heres the information you need to include:

  • your setup: distro and version, desktop environment, wayland or x11, kernel (uname -r), and hardware if its relevant (especially the GPU). inxi -Fxz gives you most of this in one go.
  • what you were trying to do
  • the exact error message copied as text. do not upload a phone photo of your monitor
  • relevant logs (get kernel logs with (sudo) dmesg, boot logs with journalctl -b (this boot), journalctl -b -1 (previous boot). see not every distro uses systemd)
  • what you already tried

now that youve got the relevant information ready, heres what to do:

  • dont ask to ask
  • ask about the real goal
  • stay there to answer questions and let people know when its resolved and what fixed it
  • be patient and polite
  • ask about commands you dont understand
  • again, ask about commands you dont understand

15. not every distro uses systemd

most guides you find online assume systemd, but its not the only init. if a guide tells you to run systemctl and you get "command not found", youre probably on one of these:

  • gentoo, alpine, artix: openrc (artix also offers runit, dinit, s6)
  • void: runit
  • youre a legend: ninit

not sure? cat /proc/1/comm tells you what your init is. (well, sysvinit shows as "init" so if it says that try rc-update to see what you have)

16. more terminal commands?

im just rambling from memory here, so maybe use read the section about how to read terminal commands. i use the terminal for pretty much everything, and these are the commands i use all the time so they must be important but ill also probably forget some and add them later

also, these arent man pages so go read them too

16.1. ln

the most common use of the ln (link) command is creating a symlink. the syntax is ln -s <target> <link name>, and the target is relative to the link

💡 tip: you can create a symlink in a folder that points to the parent folder, creating a loop. this is actually completely useless, though

16.2. grep

grep is pretty much control s (search) (it stands for global regular expression print). it is one of the best commands. to use it, you either search a file directly, or pipe somehting into it. to search foo.txt for any mention of foo, you can do this: grep "foo" foo.txt, to search dmesg for nvidia, you can do this: (sudo) dmesg | grep "nvidia". to search foo.txt for any match of "Foo", "fOo", etc (ignoring case), you can use: grep -i "foo" foo.txt. another common flag combo is this: (sudo) dmesg | grep -iE "amd|video|card". that will search dmesgs output for any mention of amd, video, or card, case insensitively.

16.3. du

disk useage, -h makes the sizes readable, and -a includes files. so pretty much you can use du -hd 1 ~ (-d 1 specifies max depth to look, you can try it with and without on your home dir to see the difference) to see the disk useage of all folders in your home dir, and use du -ahd 1 ~ to include the files too

18. glossary

appimage
a single executable that bundles an application with most of the libraries it needs. runs on any distro without being installed
atomic distro
a distro that updates the whole system as one image instead of package by package. every system update takes effect on the next reboot. bazzite and fedora silverblue are examples
aur
the arch user repository. user submitted build scripts for arch, not checked by the maintainers
block device
a device file that exposes storage in blocks, such as a disk or a partition. found in /dev
bootloader
the program the firmware runs to load the kernel. grub or systemd-boot are common
daemon
a program that runs in the background with no terminal attached, usually started by the init system. sshd and keyd are daemons
dependency
a package that another package needs to function. the package manager installs dependencies alongside the package that requires them
desktop environment
the collection of programms that together provide a window manager, panel, settings, file manager and default apps. kde plasma, gnome and xfce are examples
device file
a file under /dev that represents a piece of hardware or a kernel interface. reading and writing the file reads and writes the device
distro
a linux distribution. the linux kernel packaged with a package manager, an init system and a selection of software, maintained and released as one operating system
dotfile
a file or directory whose name starts with a period, also called a hidden file. ls does not show it without -a. most user configuration lives in dotfiles
efi system partition
a fat32 (or fat16/fat12 as per uefi standard) partition the firmware reads bootloaders from. required to boot a uefi machine. usually the first partition on the boot drive (it doesnt have to be, and you can have two on the same drive lol)
environment variable
a named value held by a process and inherited by any processes it starts. $HOME, $PATH and $USER are examples
executable bit
a file permission that allows the file to be run as a program. set with chmod +x
filesystem
the format that organizes files on a partition. ext4, btrfs and xfs are linux native, fat32, exfat and ntfs are not
flag
an argument that changes how a command behaves, written with a leading hyphen such as -r or --help. also called an option
flatpak
a package format that installs apps into a sandbox with their own runtime libraries, independent of the distros packages. flathub is the main flatpak repository
gpt
guid partition table. the modern partition table format. keeps a primary header at the start of the disk and a backup at the end
home directory
the directory a user owns for their files and configuration, usually /home/user. ~ expands to it
hostname
the name of the machine
init
the first process the kernel starts, pid 1. it starts every other service and adopts orphaned processes. systemd, openrc, ninit and sysvinit are init systems
inode
the on-disk record of a files metadata and the location of its data. a filename is a directory entry that points at an inode
kernel
the "manager" of processes, and the interface for userspace to hardware and other stuff. sometimes refered to as the "core", but i dont really like that framing, since its a part of every process (mapped into its virtual adress space) (well, not since whichever cpu vulnerability that i forgot the name of) but lets not overcomplicate this actually, just look it up it needs a whole nother article to explain 50% of it!
kernel module
kernel code loaded at runtime, usually a driver. stored under /lib/modules/VERSION as .ko files
live usb
a usb drive that boots a complete linux system without installing anything. often used to install a distro and to repair one that no longer boots
man page
manual page. read with man
mbr
master boot record. the first sector of a disk, holding a legacy partition table and some boot code
mesa
the open source implementation of opengl and vulkan. the usespace half of the graphics drivers for amd and intel gpus
mount
to attach a filesystem to a directory so its contents are reachable there. the directory is the mount point
musl
a small c standard library used in place of glibc by alpine and some other distros
nvme
a storage interface for ssds attached over pcie. the drives appear as /dev/nvme0n1, their partitions as /dev/nvme0n1p1 (note: the n1 means namespace 1, its an enterprise thing)
overlay
a third-party package repository on gentoo
package
a software component in the format the package manager installs. holds the files plus metadata such as version, dependencies and conflicts
package manager
the program that installs, removes and updates packages from repositories and tracks what is installed. apt, dnf, pacman, zypper and portage are examples
pager
a program that shows text one screen at a time. less is the usual one
partition
a region of a disk listed in the partition table. holds one filesystem or is used as swap
pid
process id. the number the kernel assigns to each running process
pipe
the | operator. connects the standard output of one command to the standard input of the next
ppa
personal package archive. a third-party repository for ubuntu
process
a running program. has a pid, a user, a working directory and environment variables
prompt
the text the shell prints when it is waiting for a command
redirection
sending a commands output to a file, or reading its input from one. > writes the file, >> appends to it, < reads from it
repository
a server holding packages and an index of their metadata. the package manager downloads from the repositories configured for the distro. abbreviated to repo
root
the user with user id 0. every permission check passes for root. also the top of the filesystem tree, /, which every path starts from
sandbox
a restricted environment that limits what a program can reach, such as files, devices and the network
service
a program the init system starts and (might) supervise(s), usually a daemon
shell
the program that reads commands from the terminal and runs them. bash is the default on most distros
signal
a notification the kernel delivers to a process
snapshot
a copy of a filesystems state at a point in time, kept on the same disk. used for rollback
standard output
the stream a program writes its normal output to, shown in the terminal unless redirected. standard error carries its error messages, standard input is what it reads (note: /dev/stdout and that are actually symlinks to /proc/self/fd/x, the more you know)
sudo
runs a command as another user, root by default, after checking that the calling user is permitted in /etc/sudoers. doas is a smaller equivalent
superblock
the record at the start of a filesystem describing its layout, size and state. the filesystem cannot be mounted without it
symlink
symbolic link. a file that holds the path to another file. most operations follow it to the target
sync
downloading the latest repository index so the package manager knows the current package versions
systemd
the init system used by most distros. also provides journald for logs, logind, networkd, timers and more
terminal emulator
a graphical program that displays a terminal for a shell to run in. like konsole, gnome terminal and foot
third-party repository
a repository not run by the distro and added by the user. ppas, overlays and the aur are examples
uid
user id. the number that identifies a user to the kernel. root is 0
userspace
everything that is not the kernel: programs, libraries, the shell and the desktop
wayland
the current display protocol, the way programs draw windows and receive input. it is replacing x11 (for the better!)
wildcard
a character the shell expands to matching filenames. * matches any string, ? matches one character. also called a glob
wine
a compatibility layer that runs windows programs on linux. proton is valves version of it for steam
working directory
the directory a process resolves relative paths against. cd changes it, pwd prints it, the prompt shows it
x11
the x window system, the display protocol used before wayland. xorg is its server
