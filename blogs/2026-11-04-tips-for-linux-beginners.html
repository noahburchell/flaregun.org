you just installed your distro of choice using the guide? brilliant! now that youre part of the team, here are some tips!

1. linux isnt windows

the old windows-isms of grabbing random executables off the web to install software, or rebooting to fix issues, or playing valorant, are gone. on linux, software is installed through the command line using a package manager (see package management), through a gui app store (if your desktop environment provides one), through flatpak, or with an appimage (see flatpak and appimage).

most issues on linux do not need a reboot, and most updates dont need one either1. unless the kernel, systemd (or whatever init youre using), graphics drivers (especially nvidia), or glibc has been updated. a reboot could also help if you genuinely dont know where to start fixing an issue. otherwise you can just leave it running

2. the terminal isnt scary

…if you learn which commands are

a lot of people advise beginners to avoid the terminal at all costs. this is counterproductive, at some point you will have to use it to fix an issue or use some tool that you want to use. if you can write /gamemode creative, you can write dnf upgrade --refresh. so how do you tell a scary command from a safe command? as a general rule, just look it up! we have google and man yknow!? (note: man is preferred in many cases) if you are told to run a command you dont understand, for example: 

find /lib/modules/$(uname -r) -iname 'nvidia*.ko*'

i think the find command would probably help find something, but im not exactly sure. so i should probably search for it!

although, before i google it maybe ill get more accurate information from the man pages included with most commands. i can access these with the command man, so in this case, man find

im also not exactly sure what the rest of it means… $(uname -r) doesnt look like a directory, maybe i should look it up! (note: if a command contains $(something), it evaluates the command (in this case something) inside the parentheses and uses its output as text. uname -r gets your kernels version string, in my case 7.3.1-lychee, so the command would expand to find /lib/modules/7.3.1-lychee -iname 'nvidia*.ko*')

bonus tip: if the command has some word or character starting with a hyphen (like -iname, -r, -rf, -a, -h) its probably a flag that goes along with the command, so for the example above you could look up "find command iname option" or something

bonus bonus tip: explainshell.com and tldr are great resources that i explain more thoroughly in where to find help, i very much recommend reading that section

now, there are certain commands to pay extra attention to

sudo / doas, rm, dd, curl | *

sudo / doas: commands that start with either of these run as root. that means, it has total privileges, it can do anything. never run a gui app as root, and if a command doesnt work, running it with sudo often will not help unless the command genuinely needs root. if you happen to run something like sudo mkdir ./foo, you will later run into issues where you cannot remove this directory or make files in it. that is because the directory is owned by root and not your user. this can be resolved with sudo chown -R $USER:$USER ./foo

rm: this command doesnt send something to the trash, it permanently deletes it and there is no undo. the most common failiure is most often not rm -rf / or something like that, but rm -rf $DIR/*. $DIR should expand to /home/user/some/trash, but if it has been unset, it will expand to "" and the command rm -rf /* will run

dd: this command writes data somewhere, youll often see: 

dd if=/some/diskimage.iso of=/dev/sdX bs=4M status=progress conv=fsync

this is not inherently unsafe, its actually the standard way to create a bootable usb. it becomes dangerous if of=/dev/sdX is the wrong location. luckily there is a small habit that makes it very safe, always run lsblk before running dd. lsblk will show you all of the drives connected to your computer, making it easy to determine the correct one.

but just so you know, if the location you typed (for example /dev/sda) is your boot drive2 or a drive with your stuff on it, depending on the size of the disk image, youll overwrite:

  1. the protective mbr
  2. the primary gpt header and partition table3
  3. the entire efi system partition
  4. the beginning of the next partition, and its superblock
  5. if the input never ends (if=/dev/zero), then literally everything

so always double check its correct with lsblk

curl https://example.com/example.sh | bash or the more evil version curl https://example.com/example.sh | sudo bash: these commands download a script from that site and execute it immediately without showing you what its doing. never do this blindly. if a site wants you to install their software like this, first make sure the site is trustworthy, then download it alone (curl -LO https://example.com/example.sh), then use ls to check the filename, then with that information run less ./example.sh to review it, then you can run it by first making it executable (chmod +x ./example.sh), and executing it like so: ./example.sh

> vs >>

i dont want to go too much into teaching shell, but this one difference is worth a note. these are redirection operators, as an example: echo "gentoo" > gentoo.txt will do this4: 

noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ %

now, lets look at what >> will do: 

noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ % echo "gentoo" >> gentoo.txt 
noah@lychee ~ % cat gentoo.txt             
gentoo
gentoo
noah@lychee ~ %

now, lets use > again on the same file: 

noah@lychee ~ % echo "gentoo" > gentoo.txt
noah@lychee ~ % cat gentoo.txt 
gentoo
noah@lychee ~ % echo "gentoo" >> gentoo.txt 
noah@lychee ~ % cat gentoo.txt             
gentoo
gentoo
noah@lychee ~ % echo "gentoo" > gentoo.txt 
noah@lychee ~ % cat gentoo.txt            
gentoo
noah@lychee ~ %

notice the difference here, > will truncate the file5 and replace it with what its given. >> on the other hand will append to the file, not overwriting the content. (if there is no file, then they act the same for all intents and purposes)

3. you learnt windows, you can learn linux

i think its called the curse of knowledge, where you forget what it was like to not know? whatever it is, the point is that at some point you had to learn how to use windows, you had to learn how to search for an app, you learnt what a sketchy vs safe download looked like6. so you should expect to have to learn how to use linux, learn how to use the package manager (see package management) for apps, learn how your desktop works, and, dont be discouraged if you fuck something up7. youre learning!

4. package management

the most common way to install software on linux is through the package manager. common package managers include: apt, dnf, pacman, zypper and portage. (note: for alternatives such as flatpak and appimage, see flatpak and appimage). to communicate with these package managers, you will use the terminal, here are examples for each of the package managers mentioned:

apt:

  • installing a package: apt install whatever
  • removing a package: apt remove whatever (or apt purge whatever to also delete config files)
  • syncing repos: apt update
  • updating everything: apt upgrade8
  • searching for a package: apt search whatever

dnf:

  • installing a package: dnf install whatever
  • removing a package: dnf remove whatever
  • syncing repos: dnf makecache (dnf usually does this automatically)
  • updating everything: dnf upgrade
  • searching for a package: dnf search whatever

pacman:

  • installing a package: pacman -S whatever
  • removing a package: pacman -R whatever (or pacman -Rns whatever to also remove unneeded dependencies and config files)
  • syncing repos + updating everything: pacman -Syu9
  • searching for a package: pacman -Ss whatever

zypper:

  • installing a package: zypper install whatever
  • removing a package: zypper remove whatever
  • syncing repos: zypper refresh
  • updating everything: zypper update (on tumbleweed use zypper dup instead)
  • searching for a package: zypper search whatever

portage:

  • installing a package: emerge -a whatever
  • removing a package: emerge -a --deselect whatever then emerge --depclean
  • syncing repos: emerge --sync
  • updating everything: emerge -auDN @world
  • searching for a package: emerge --search whatever

installing or updating packages and syncing most often requires root privileges, so make sure to run those commands with sudo or doas

now that you know how to use it, its important to know what youre doing and why it is this way. briefly, your distros maintainers have a "repo" (repository) that is pretty much a sort of database of packages. it contains the package and metadata for each one that is used when you install that package. this may include dependencies and packages its incompatible with. what is a dependency? its another package that the package needs to function correctly. so when you ask the package manager to install a package, it may install a few packages alongside it if it depends on them. also, your package manager will most likely verify the integrity of the package and that it came from a trustworthy source after it downloads it (one of the many reasons this approach is far superior to the windows approach). "syncing" just means updating the database.

dont delete your desktop

you may have seen that… situation linus was in when he deleted his desktop using pop os. this was caused by a packaging mistake with steam, but linus could have avoided this, and you can too, so heres how:

just listen to your package manager! it sounds simple, of course, but many people tend to just hit yes on autopilot. this is normal, but you should avoid this behavior as the output of your package manager is not useless monospace text, its telling you exactly what it is going to do! now, you might mention that you wouldnt know removing, say, glibc10 was any different to removing libcaca, thats reasonable. so the best advice i can give you is to research anything youre unsure about. scan the package managers output for keywords like "desktop" (gnome-desktop, plasma-desktop), "system", "wayland", "xorg", "mesa", "base", "systemd" to make sure nothing important is being removed, and if youre even slightly unsure, just look it up. be very attentive if your package manager asks you to do something unusual, such as asking you to type "yes do as i say!" to continue. over time, you will learn what is important and whats not, so dont worry, you wont be stuck looking things up for very long, it just comes with time.

be careful with third-party packages

sometimes, youll need something that isnt available in your distros official repo. in these cases, youll typically want to either add a third-party repository (like a ppa on ubuntu or an overlay on gentoo) or use a third-party source (such as the aur on arch). this is incredibly valuable, but it should be used carefully.

a third party package:

  • isnt checked by distro maintainers
  • can conflict with or replace official packages, leading to issues updating
  • can be outdated or unmaintained (security worry)
  • can, in very rare cases, just be malicious (google: "aur incident")

so, make sure you check the official repos or flatpak11 for the package first.

tip: remove third-party repos you dont use anymore

7. where to find help

there are many great resources for finding help with anything you need to know about linux

7.1. for general advice

often the best way to get help with your distro is to find your distros specific wiki, such as the arch wiki or gentoo wiki. also, there tends to be a discord server available, official or unofficial, with people there that like helping newcomers

the arch wiki tends to be particularly helpful even if you are not using arch, as it covers certain distro-agnostic topics very well

on llms:

yes, they have gotten much better, and they can generally be trusted (especially premium models) with certain tasks. with a catch. this is only true if you understand what the model is telling you. you might find it helpful to add system instructions that instruct the model to explain the commands its giving you, or just asking it about parts of the advice you dont understand. so, while powerful for people who already somewhat know what theyre doing, id advise beginners to be cautious

7.2. for specific commands

tldr

this command is unlike man in that you will need to install it, but it is often more helpful for beginners as it gives short, example-based summaries, and a full man page is sometimes overwhelming

man

this command is an interface for manual pages, typing man foo will bring up the manual page for foo. this is good becasue the information there will (usually) be specific to the exact version of the software you have installed, though it is quite dense and assumes you already know what youre doing a lot of the time

explainshell.com

i never knew about this site until recent! its great, and i wish someone told me about it sooner. it breaks a command down piece by piece, and makes it easy to understand. the only note is that it sometimes lags behind and may not know about a very new flag
